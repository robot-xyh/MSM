# 第一部分：威胁环境与总体架构

---

## 一、威胁环境分析

### 1.1 全威胁谱系

现代野战防空作战面临多类型、多高度、多速度的复合空中威胁。根据俄乌冲突实战数据，旅级合成部队在防御作战中可能同时遭遇以下威胁：

| 威胁类型 | 典型装备 | 单枚成本 | 单波次数量 | 飞行速度 | 典型高度 | 威胁评级 |
|----------|----------|----------|-----------|----------|----------|----------|
| 远程火箭弹 | BM-30型300mm | 15万美元 | 12-24枚 | Ma 3 | 弹道高点30km+ | 高 |
| 巡航导弹 | Kh-101 | 1300万美元 | 5-20枚 | 900km/h | 30-100m | 极高 |
| 近程弹道导弹 | Iskander-M | 3000万美元 | 1-5枚 | Ma 6+ | 弹道 | 极高 |
| 大型自杀式无人机 | Shahed-136 | 2万美元 | 50-120架 | 185km/h | 100-300m | 极高 |
| 巡飞弹 | Lancet-3 | 3万美元 | 10-30架 | 110km/h | 200-1000m | 高 |
| 小型FPV自杀机 | 各型改装FPV | 500-2000美元 | 50-200架/日 | 150km/h | 10-200m | 高 |
| 侦察无人机 | Orlan-10/ZALA | 10万美元 | 5-20架 | 90km/h | 500-3000m | 中 |

### 1.2 无人机威胁的紧迫性

2026年1月，乌克兰武装力量单月截击Shahed-136型无人机达1704架（The Economist, 2026年2月）。同期FPV自杀机日均出动量超过200架次。上述两类无人机占全部空中威胁数量的百分之八十五以上。

成本不对称是制约传统防空体系效能的核心矛盾。NASAMS系统配属的AIM-120系列拦截弹单价约100万美元，截击单价2万美元的Shahed-136，成本比为50:1。按俄军日均100架Shahed计算，若全部使用中程防空导弹拦截，日均弹药消耗将达1亿美元，不具备持续作战的可行性。

乌克兰武装力量的实战数据表明，截击Shahed的作战任务中约百分之七十由FPV拦截无人机完成（ukraine-war-analytics.com, 2026年2月），而非传统防空导弹。一架成本300至600美元的改装FPV竞速无人机，可实现对单价2万美元的Shahed-136的有效毁伤，效费比达1:50至1:150。

### 1.3 核心问题

传统防空体系的设计基准是拦截高价值空中目标（战斗机、巡航导弹），其拦截弹药成本与目标成本匹配。当威胁形态转变为低成本饱和攻击时，拦截成本远超威胁成本，形成不可持续的经济消耗战。

本报告论证的核心命题：构建以无人机反无人机为基本手段的野战防空体系，使拦截成本与威胁成本恢复对称，达成可持续的防御能力。

## 二、总体架构：三层防御圈与复合探测网

### 2.1 体系构成

本体系由一网三层构成：一套复合探测感知网，加三层火力拦截圈。

复合探测感知网由三类传感器构成：

| 传感器类型 | 作用高度域 | 作用距离 | 部署方式 | 核心优势 | 使用限制 |
|-----------|-----------|----------|----------|----------|----------|
| 声学传感器阵列 | 200m以下 | 外环8km/内环4km | 地面布设，环形配置 | 全被动，零辐射，成本低 | 高空目标不可靠 |
| 地面雷达网 | 500m以上 | 主雷达60km/角站15km | 中心站+四角站 | 全天候，精确航迹 | 低空受曲率限制 |
| 系留浮空器 | 全高度域 | 200km+ | 升空3000m | 视距优势，24小时 | 大风需回收 |

三层火力拦截圈：

第一层，30km拦截圈。配属中程防空导弹（IRIS-T SLS级别），射程12km，成本约40万美元每枚。主要任务为拦截巡航导弹与高空大型无人机。使用原则：不对低成本无人机目标使用，仅保留用于高价值威胁。

第二层，10km拦截圈。本体系的核心拦截层，配属群反群拦截无人机系统与35mm高炮。群反群系统承担约百分之七十拦截任务，单次拦截成本约500至650美元；35mm高炮承担约百分之十五拦截任务，单次拦截成本约1500至3000美元。使用原则：优先使用群反群系统实施拦截，高炮用于补漏。

第三层，末端拦截圈。配属MANPADS单兵防空导弹（成本约5万美元每枚）与定向电子干扰设备（零成本每次）。主要任务为截击突破前两层的残余目标。

伪装欺骗层（底层）。对全部雷达阵地、指挥节点、发射阵地实施伪装，部署假目标系统诱敌消耗。全系统伪装与假目标成本约45万美元，占装备总投资的百分之零点六。

### 2.2 探测网的协同机制

三类传感器在高度域上互补：200m以下以声学传感器为主，该高度域受地球曲率遮挡，地面雷达视距严重受限，且无人机RCS仅0.01至0.05平方米，进一步压缩有效探测距离；200m至500m以光电与天哨无人机补盲；500m以上以地面雷达网与系留浮空器雷达为主。

典型协同流程（以Shahed-136蜂群来袭为例）：系留浮空器雷达在245km外捕获目标航迹（T-79分钟）到声学外环在8km外声纹确认目标类型（T-10分钟）到声学内环在4km外提供精确方位（T-5分钟）到天哨无人机升空红外光电锁定目标（T-2分钟）到猎蜂群起飞拦截（T-1分钟）。

### 2.3 指挥决策逻辑

旅属防空指挥所的核心决策任务为：依据目标类型、威胁等级、可用资源，按效费比最优原则自动分配拦截手段。决策流程为：目标分类（声学指纹加雷达航迹加光电图像判定目标类型）到威胁评估（目标飞行方向、距离、速度进行威胁排序）到武器匹配（按效费比从低到高依次分配电子干扰、猎蜂群反群、高炮、MANPADS、中程导弹）到执行与评估。

### 2.4 三层防御圈与复合探测网的融合逻辑

三层防御圈不应理解为三个彼此独立的火力区，而应理解为同一套目标航迹在不同距离、不同高度、不同置信度阶段下的资源接管关系。复合探测网负责生成统一目标航迹，三层防御圈只消费同一份融合态势。

融合流程可分为五个状态：

| 状态 | 触发条件 | 主要传感器 | 系统动作 |
|------|----------|------------|----------|
| 疑似目标 | 单一传感器发现异常 | 声学、雷达、ESM或光电 | 建立临时航迹，不分配拦截资源 |
| 确认目标 | 两类传感器一致，或单类传感器连续稳定跟踪 | 雷达+光电，声学+光电 | 生成全局目标ID，进入威胁排序 |
| 交战质量航迹 | 位置、速度、类别和协方差满足分配要求 | 雷达/光电/浮空器融合 | 允许进入资源分配队列 |
| 拦截中 | 已有拦截资源接管 | 天哨、猎蜂、地面C2 | 持续更新预测点和任务状态 |
| 效果评估 | 目标消失、坠落、热源消失或航迹中断 | 光电、雷达、声学 | 判定成功、失败或需要补位 |

三层防御圈按目标价值和交战窗口接管同一目标：外层优先处理高价值、高速度、高高度威胁；中层处理大批量低成本无人机；末端处理漏网目标。中心节点不直接把“传感器发现”映射为“立即拦截”，而是先经过航迹确认、威胁排序和资源可行性检查。

统一航迹建议采用如下抽象字段：

```text
GlobalTrack
- global_track_id
- source_track_ids
- timestamp
- position_ned
- velocity_ned
- covariance
- classification
- confidence
- threat_score
- track_state
- assigned_resource_id
- handover_state
```

其中 `covariance` 表示定位不确定性，`track_state` 表示 tentative、confirmed、engageable、engaged、lost、dropped 等状态，`handover_state` 表示当前目标处于哪一个探测系统或防御圈的接管阶段。

### 2.5 来袭目标定位方法

来袭目标定位应采用“多源观测、统一坐标、带不确定性输出”的原则。不同传感器提供的不是同一种信息：

| 传感器 | 主要观测量 | 定位作用 | 局限 |
|--------|------------|----------|------|
| 声学阵列 | 到达时间差、方位、声纹类别 | 低空粗定位和早期告警 | 距离精度有限，受风和噪声影响 |
| 地面雷达 | 距离、方位、俯仰、径向速度 | 三维位置和速度主来源 | 低空遮挡、近地杂波 |
| 浮空器雷达 | 大范围距离、方位、速度 | 远距预警和高空补盲 | 易受气象和平台稳定性影响 |
| 光电/红外 | 像素框、角度、类别、热源 | 目标确认、末端识别、效果评估 | 单目距离不稳定，受天气影响 |

定位链路如下：

```text
本地传感器观测
-> 时间戳对齐
-> 坐标转换到统一NED坐标系
-> 观测协方差建模
-> 航迹预测
-> 数据关联
-> 滤波更新
-> 输出GlobalTrack
```

声学阵列通常先给出粗方位和类别置信度；雷达给出可用于融合的三维位置和速度；光电系统主要用于确认类别、降低误警和在目标交叉时辅助维持ID。单目光电不宜单独承担远距离三维定位任务，除非配合测距、双目/多目几何或已有雷达距离。

### 2.6 多目标配准与航迹管理

多目标配准的核心问题是：同一个真实目标会被多个传感器、多个视场、多个节点同时发现，系统必须判断这些局部观测是否属于同一个全局目标。

配准分三层：

1. **传感器内配准**：同一雷达或同一相机内部连续帧之间的目标关联。
2. **跨传感器配准**：雷达航迹、声学方位、光电检测框之间的关联。
3. **跨节点配准**：不同雷达站、天哨、地面站生成的局部航迹之间的关联。

推荐关联判据：

```text
时间门限：观测时间差在允许范围内
空间门限：观测位置落入预测协方差门限
速度门限：速度方向和大小与已有航迹一致
类别门限：声纹/图像/雷达特征分类不冲突
历史门限：连续多帧关联优先于单帧强匹配
```

多目标航迹状态机：

| 状态 | 含义 | 处理 |
|------|------|------|
| tentative | 新建但未确认 | 暂不分配拦截资源 |
| confirmed | 多帧稳定或多源一致 | 进入威胁排序 |
| engageable | 定位精度和类别置信度满足要求 | 可参与资源分配 |
| engaged | 已有资源接管 | 持续更新和防止重复分配 |
| lost | 短时丢失 | 用预测维持，限制新分配 |
| dropped | 超时未恢复 | 释放资源并归档 |

当目标交叉、编队密集或视场切换时，系统应记录 `id_switch_count`。若同一目标在融合系统中频繁更换ID，会导致重复分配、漏分配或补位错误，因此ID稳定性应作为多目标系统的核心指标，而不只统计命中率。

### 2.7 多探测系统交接与不同视场目标关联

探测系统交接不是简单的“雷达交给光电”或“外圈交给内圈”，而是航迹主导权的转移。建议采用 `handover_token` 机制：每个 `GlobalTrack` 同一时刻只有一个主传感器负责主更新，其他传感器作为辅助更新源。

典型交接链路：

```text
浮空器雷达远距发现
-> 地面雷达接力稳定三维航迹
-> 声学阵列低空确认方向和类别
-> 天哨光电获取图像确认
-> 拦截资源末端传感器接管
-> 光电/雷达进行效果评估
```

不同视场下同一目标的关联方法：

| 情况 | 关联方法 |
|------|----------|
| 广域雷达到窄视场光电 | 用雷达预测位置控制光电指向，再用角度门限关联 |
| 广角光电到长焦光电 | 先保持同一平台姿态解算，再比较目标角速度和外观特征 |
| 天哨视场到猎蜂视场 | 使用目标方位、预测位置、外观类别和接管时间窗联合判断 |
| 两个雷达站重叠覆盖 | 使用位置协方差、速度一致性和历史航迹连续性判断 |

交接失败时不应立即删除目标，而应进入短时 `lost` 状态，由上一主传感器预测维持；若新传感器在时间窗内重新捕获，则恢复原 `global_track_id`，避免因视场切换产生新目标ID。

### 2.8 拦截资源与目标分配

本文中的“武器目标分配”在系统工程上建议表述为“拦截资源-目标分配”。其输入是已确认目标集合和可用拦截资源集合，输出是任务配对、优先级和备份关系。该过程应保留人工授权接口，尤其在真实环境中不得由模型绕过指挥员直接执行不可逆动作。

分配输入：

```text
TargetSet = confirmed / engageable GlobalTrack
ResourceSet = 可用拦截资源、剩余数量、状态、覆盖范围、任务占用
ConstraintSet = 禁区、友邻空域、最小间隔、人工授权状态
```

威胁评分可按抽象因素计算：

```text
threat_score = 目标类型权重
             + 接近保护区域程度
             + 预计到达时间紧迫性
             + 航迹置信度
             + 饱和攻击中的编队位置
```

资源分配代价可按抽象因素计算：

```text
assignment_cost = 拦截窗口代价
                + 资源消耗代价
                + 航迹不确定性惩罚
                + 重复分配惩罚
                + 友邻冲突惩罚
                + 备用资源占用惩罚
```

集中式中心节点可采用 Hungarian、最小费用最大流或滚动窗口优化；分布式节点可采用拍卖式协商或一致性分配。为避免频繁重分配，应设置迟滞条件：只有当新分配显著优于旧分配，或旧任务不可行时才切换。

默认分配原则：

1. 高威胁目标优先获得拦截资源。
2. 低成本、低附带风险资源优先使用。
3. 一个目标默认只分配一个主拦截资源，另可保留一个备份资源。
4. 同一资源同一时刻只执行一个主任务。
5. 航迹不确定性过大时先请求进一步确认，不直接进入不可逆处置。

## 三、群反群子系统总体设计

### 3.1 定义与定位

群反群拦截子系统是指以多架低成本自杀式无人机为拦截手段，以分布式协同通信为组织方式，以机载AI视觉识别为末端制导手段的自主化反无人机作战系统。

该系统在野战防空体系中的定位为三种模式：融入大体系模式（接收旅指挥所的目标分配指令执行拦截任务，拦截效能最高）；独立作战模式（旅指挥所失效时，地面反无小站接替指挥功能，独立完成目标搜索、分配、拦截全流程）；单兵便携模式（无任何体系支持时，单兵携带4架猎蜂无人机及手持终端，依靠目视听觉发现目标，实施近距离拦截）。

### 3.2 系统三层架构

群反群系统内部分为三层：指挥层、协同层、执行层。

指挥层由天哨无人机承担。天哨为一型小型固定翼垂直起降无人机，升空至1000至3000m高度，搭载三光光电吊舱（可见光30倍连续变焦、中波红外热成像、激光测距）及边缘AI计算单元。主要功能为广域空中态势感知、多目标检测与分类、目标分配决策生成、打击效果评估。

协同层由猎蜂无人机之间的Mesh自组网通信网络构成。各机仅需与相邻节点通信，通过多轮协商达成目标分配共识，不依赖中心节点统一调度。此架构参考了浙江大学李荣鹏团队提出的ConsMAC去中心化共识通信机制。

执行层由猎蜂无人机构成。猎蜂为一型7至10英寸级别的高速四旋翼无人机，搭载微型摄像头与AI视觉锁定芯片、200至300g定向破片战斗部。主要功能为接收目标数据、自主规划拦截航路、末端视觉锁定、动能撞击毁伤。

### 3.3 去中心化协同的设计依据

传统集中式指挥架构存在单点失效风险，指挥节点被摧毁则全系统瘫痪。去中心化架构将决策权分布至各作战节点，即使部分节点失效，其余节点仍可继续执行任务。这一设计理念已在乌克兰战场上得到初步验证：机动火力小组在无统一指挥时，各小组依赖Starlink共享Shahed航迹信息，自主选择拦截阵位，实现了分布式协同拦截。

## 四、指挥层：天哨无人机系统

### 4.1 装备参数

| 参数 | 指标 |
|------|------|
| 机型 | 固定翼+垂直起降 |
| 巡航高度 | 1000-3000m |
| 续航 | 60-90分钟（电池）/ 24小时（系留） |
| 任务载荷 | 三光吊舱（可见光+红外+激光测距） |
| 边缘计算 | 6 TOPS NPU |
| 通信 | Mesh自组网（15km）+ 光纤互联 |
| 单机成本 | 8000-12000美元 |
| 战斗载荷 | 无（仅承担ISR与C2功能） |

### 4.2 目标分配机制

天哨机载AI计算单元完成以下处理流程：光电吊舱广域扫描检测空中目标；深度学习模型分类（三角翼加推进式螺旋桨判定为Shahed-136；四旋翼加小型机身判定为FPV；固定翼加喷气动力判定为巡航导弹）；对每架己方猎蜂计算最优拦截配对，优化目标为最小化拦截航程、最大化威胁覆盖、避免重复分配；生成分配方案通过Mesh网络下发至各猎蜂。目标分配算法的响应延迟需控制在10ms以内。

## 五、协同层：去中心化通信网络

### 5.1 通信架构

| 通信层级 | 链路类型 | 作用距离 | 带宽 | 抗干扰 |
|----------|----------|----------|------|--------|
| 天哨到猎蜂 | Mesh广播 | 15km | 1Mbps | 跳频+扩频 |
| 猎蜂到猎蜂 | k-近邻Mesh | 5km | 500kbps | 短距低功率 |
| 备份链路 | LoRa | 10km | 50kbps | 超低功率 |
| 地面站互联 | 光纤 | - | 100Mbps+ | 不受电磁干扰 |

### 5.2 协同协商流程

当指挥层失效（天哨被击落）时，协同层接替目标分配功能：每架猎蜂通过自身传感器获取局部态势，与k个最近邻节点交换观测数据，利用ConsMAC共识算法各机独立计算全局最优分配方案，经过3至5轮通信迭代后各机对目标分配达成一致，各机执行分配到的拦截任务。

### 5.3 全通信中断的降级模式

当Mesh网络与LoRa备份均被全频段压制时，猎蜂自动切换至自主搜索-识别-拦截模式：在预设巡逻空域内按预定航线自主巡航，机载AI视觉系统持续扫描空域，检测到目标后独立评估（三角翼加推进桨特征判定为Shahed遂行拦截，鸟类轮廓判定为非目标忽略），末端AI视觉锁定后加速撞击。此模式下拦截效率降至完好模式的百分之四十至五十，但系统不失效。

### 6.3 典型作战流程

以猎蜂17号截击Shahed42号为例：待命状态（猎蜂在发射箱内，系统预热完成）到接收任务（天哨下发目标数据，发射箱开盖，猎蜂垂直起飞）到飞向目标（爬升至目标同高度，全速飞向预测拦截点）到末端锁定（距目标500m时机载AI视觉确认目标特征，进入自主末端制导）到撞击毁伤（以250km/h相对速度撞击，战斗部引爆，目标解体，猎蜂自毁）到战果确认（天哨红外确认目标热源消失，未命中则指派备用机补位）。

### 6.4 兵力运用计算

成本核算：猎蜂消耗80架乘以600美元等于4.8万美元；35mm高炮弹药200发乘以500美元等于10万美元；MANPADS3枚乘以5万美元等于15万美元。单次80架拦截总成本约29.8万美元。拦截目标价值80架乘以2万美元等于160万美元。效费比1:5.4，防御方优势。

与纯导弹方案对比：若全部使用AIM-120（100万美元每枚，命中率百分之八十）拦截，需100枚等于1亿美元。群反群方案的拦截成本为纯导弹方案的百分之零点三。

## 七、三级降级生存能力

### 7.1 降级路径

状态一（全功能运行）：天哨加协同网加猎蜂三层完好。拦截效能为基线水平（命中率80-90%）。

状态二（指挥层失效）：天哨被击落，地面反无小站接替指挥功能。协同层通信网与猎蜂群完好。拦截效能降至完好状态的70-80%。

状态三（指挥层加协同层全部失效）：天哨被击落，Mesh网加LoRa被全频段压制。猎蜂转入自主搜索-识别-拦截模式。拦截效能降至完好状态的40-50%。

状态四（最后底线）：猎蜂全部消耗。依次转入35mm高炮、MANPADS、电子干扰、目视加轻武器拦截，效能大幅下降但永不归零。

### 7.2 设计原理

降级生存能力的设计基于功能解耦与多层次冗余：指挥功能不依赖单一节点（天哨空中、地面站地面、单兵目视人力三层接替）；通信功能不依赖单一链路（Mesh主、LoRa备、视觉自主无通信三层接替）；拦截功能不依赖单一手段（猎蜂主、高炮备、MANPADS补、轻武器最后）。乌克兰战场经验表明，俄军首轮打击通常能摧毁固定雷达阵地和指挥节点，但机动火力小组和单兵防空武器仍能维持一定拦截能力。本体系的设计目标是将这种残存作战能力从被动应急提升为主动设计。

### 7.3 中心节点失效后的切换机制

中心节点失效不应由单一“掉线”事件触发，而应由健康监测状态机判断。建议每个节点维护 `C2Health`：

```text
C2Health
- heartbeat_age
- last_track_update_age
- assignment_update_age
- command_ack_rate
- clock_sync_error
- link_quality
- health_state
```

`health_state` 可分为 normal、degraded、suspect、failed 四级。只有当心跳中断、航迹更新中断、任务分配更新中断同时满足超时条件时，才进入 failed，避免短时链路抖动导致全网误切换。

切换流程：

```text
中心节点normal：所有节点接收中心融合航迹和分配结果
中心节点degraded：分布式节点开始缓存本地观测和邻居观测，准备接管
中心节点suspect：候选备份节点发起接管投票，冻结非必要重分配
中心节点failed：备份节点或分布式共识层接管航迹融合与任务分配
中心节点恢复：进入双轨校验，不立即夺回控制权
```

接管节点优先级建议：

1. 地面反无小站，具备供电、算力和多链路接入，优先接管。
2. 天哨备份机或高空中继节点，具备较大视场，次优先接管。
3. 猎蜂集群代表节点，仅在前两者不可用时接管局部任务。
4. 单兵终端或人工观测点，只提供局部确认和人工授权。

中心恢复后不应直接覆盖分布式态势，而应执行航迹合并：

```text
中心恢复航迹表
-> 与分布式航迹表按global_track_id/source_track_ids匹配
-> 对冲突航迹进行人工或规则确认
-> 保留已执行任务状态
-> 再逐步恢复中心主控
```

### 7.4 分布式节点的自主决策边界

分布式节点接管后，其目标不是复制完整指挥所，而是在信息不完整条件下维持局部防御能力。自主决策应分为三类：

| 决策类型 | 可自动执行 | 需要人工确认 | 禁止自动越权 |
|----------|------------|--------------|--------------|
| 态势维护 | 本地检测、航迹预测、邻居观测融合 | 航迹身份冲突 | 篡改其他节点历史记录 |
| 任务协商 | 候选目标排序、资源占用声明、冲突消解 | 高不确定性目标处置 | 绕过授权执行不可逆动作 |
| 生存控制 | 返航、待机、通信重连、避碰 | 改变任务区域 | 进入禁区或友邻空域 |

分布式自主决策的基本原则：

1. **保守确认**：单节点单帧观测只建立 tentative 航迹，不直接进入处置。
2. **局部一致**：相邻节点对目标ID、类别和任务占用达成一致后再执行。
3. **冲突优先**：如果任务分配与避碰、禁区或友邻识别冲突，优先中止或等待。
4. **可追溯**：每次分布式分配必须记录参与节点、输入航迹、分配版本和决策原因。
5. **人机边界**：涉及真实不可逆处置时，应保留人工授权或预先设定的仿真约束。

### 7.5 分布式航迹融合与任务协商

中心节点失效后，各分布式节点维护局部航迹表：

```text
LocalTrackTable
- local_track_id
- estimated_global_id
- source_node_id
- timestamp
- position_ned
- velocity_ned
- covariance
- classification
- confidence
- observed_by_neighbors
```

节点之间交换的不是原始视频或全量雷达数据，而是压缩后的航迹摘要和资源状态：

```text
TrackSummary
- estimated_global_id
- timestamp
- position_ned
- velocity_ned
- covariance
- classification
- confidence

ResourceSummary
- node_id
- resource_id
- availability
- current_task_id
- energy_state
- local_constraints
```

分布式任务协商可采用拍卖式流程：

```text
每个节点根据本地航迹计算目标优先级
每个可用资源对候选目标计算本地代价
节点广播自身出价和任务占用声明
邻居节点比较出价，低代价者获得临时任务权
若出现冲突，按航迹版本、节点优先级和代价差消解
若多轮后未收敛，保留原任务或进入待命
```

这种方式的优势是通信量小、可局部收敛；缺点是全局最优性不如中心节点。因此报告中的分布式模式应定位为“中心失效后的韧性保底能力”，而不是正常状态下的首选模式。

### 7.6 分布式节点自主决策的仿真验证指标

为避免只用命中率评价系统，应增加以下韧性指标：

| 指标 | 含义 |
|------|------|
| failover_time | 中心失效到备份/分布式接管的时间 |
| track_continuity | 切换前后航迹ID保持率 |
| id_switch_count | 多目标交叉或交接导致的ID切换次数 |
| duplicate_assignment_count | 多个资源重复分配同一目标的次数 |
| unassigned_high_threat_count | 高威胁目标未被分配的次数 |
| consensus_rounds | 分布式协商达到一致所需轮数 |
| degraded_completion_rate | 降级模式下任务完成率 |
| human_override_count | 人工介入次数 |

仿真实验应覆盖三类故障：

1. 中心节点突然失效，但Mesh仍可用。
2. 中心节点失效，同时部分探测节点丢失。
3. 中心节点失效，同时通信延迟、丢包和局部节点失效并存。

验证目标不是追求全自主攻击，而是证明系统在中心失效时仍能保持态势连续、任务不重复、资源不互相冲突，并在不确定性升高时自动降级为等待、确认或人工接管。

## 十一、指挥控制与费用优化

### 11.1 指挥界面设计

指挥所态势显示屏以热力图呈现战场空中态势：绿色区域无异常，黄色为声学网络检测到疑似目标，橙色为目标确认跟踪中，红色为目标进入拦截交战圈。指挥员确认自动拦截后，系统按效费比排序自动分配拦截手段，指挥员保留手动越权控制的权限。

### 11.2 C2数据总线与模块接口

为支撑复合探测网、多层防御圈和分布式降级运行，C2系统建议采用统一数据总线，而不是由各传感器直接驱动各拦截资源。核心数据对象如下：

```text
- source_track_ids
- timestamp
- position_ned
- velocity_ned
- covariance
- classification
- confidence
- threat_score
- track_state

ResourceState
- resource_id
- resource_type

- health_state

AssignmentPlan
- plan_id

- target_track_id
- primary_resource_id

```

C2处理链路建议为：

```text

-> 全局航迹融合
-> 威胁评分
-> 资源可行性筛选
-> 资源-目标分配
-> 人工确认/规则确认
-> 任务发布
-> 效果评估
```

该结构的优点是传感器、融合算法、资源分配算法和显示界面之间解耦。后续在仿真中替换传感器模型、分配算法或通信模型时，不需要重写全系统。

### 11.3 人机协同与授权状态

为避免自动系统在高不确定性条件下做出不可逆决策，建议所有任务计划维护 `human_authorization_state`：

| 状态 | 含义 | 系统行为 |
|------|------|----------|
| observe_only | 仅观察 | 只跟踪和显示，不分配处置资源 |
| recommend | 系统推荐 | 生成分配建议，等待确认 |
| authorized | 已授权 | 按规则发布任务 |
| hold | 暂停 | 保持航迹，不继续升级 |
| abort | 中止 | 释放资源，记录原因 |

在学术仿真中，可以用规则模拟授权状态；在任何真实系统讨论中，不应让模型绕过授权状态直接执行不可逆动作。
