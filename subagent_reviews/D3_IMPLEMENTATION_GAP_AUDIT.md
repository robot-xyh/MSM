# D3 实现差距审计

**模块**: D3 集中式资源-目标分配  
**审计范围**: `subagent_reviews/D3_ASSIGNMENT_PLANNER_REVIEW_AND_PLAN.md`、`C_UAS_MAINSTREAM_SOLUTIONS_AND_DIFFICULTIES.md`、`research_modules/d3_assignment_planner/` 代码与测试。  
**边界**: 本审计只覆盖离线科研仿真中的抽象资源-目标分配、计划版本、终端反馈合同和 AirSim dry-run 适配；不涉及真实飞控、硬件、火控、毁伤或自动处置。

## 1. 总体结论

D3 已实现中心化 1 对 1 分配主线：`SciPy linear_sum_assignment`/Hungarian、fallback 动态规划、可解释代价矩阵、滚动重分配、迟滞、版本化 `AssignmentPlan`、stale plan 拒绝、D5 terminal feedback 保守决策 helper、D7 dry-run 用 `AssignmentGuidanceBinding`/`guidance_bindings_from_assignment_plan`，以及 synthetic AirSim dry-run 输入适配。

仍未实现的主要是复杂约束和运行时闭环接线：OR-Tools 最小费用流仅保留接口；D5 terminal feedback 已映射为 main 动作和 planner metadata，但不会在 D3 内自动改写成本矩阵；AirSim dry-run 只接收合成 dict/object，不接入 AirSim/Blocks runtime；二级节点仲裁和 CBBA 属于 D4，不在 D3 当前实现内。`AssignmentValiditySummary` 和 D3 到 D6 的 `AssignmentRecord` 导出 helper 已代码化。

与 `MAIN_IMPLEMENTATION_GAP_AUDIT.md` 的 P0/P1 状态对齐如下：D3 到 D7 的版本化绑定属于 **P0 已补齐**；D3 仍需 main 统筹的 **P1 运行时闭环** 包括把真实 D1/D2/D3/D4/D5 流接入 5v5 AirSim 状态机、把 D5 的 `locked/ambiguous/hold/reacquire` 和 duplicate lock 事件写入 D3/D7/D6 闭环、以及把主动降级细分指标交给 D6 聚合。OR-Tools Min Cost Flow 属于复杂约束升级项，按 main 审计为 **P1/P2 可选对照/升级**，不是当前 P0 阻塞项。

## 3. 关键缺口按优先级排序

1. **P0 已完成**: D3 到 D7 的 `AssignmentGuidanceBinding` 已实现并有契约测试；D3 侧不再缺少版本化 guidance binding。
2. **P1 接口已完成，运行时接线待 main**: D5 terminal feedback 现在输出 `main_action` 和 `planner_metadata`，明确映射 `hold/replan/secondary_arbitration`、`operator_hold`、禁配边、`feasibility_by_resource`、`fov_difficulty_by_resource`、D7 gate 和 D4 仲裁请求。main 仍需实际把这些 metadata 写入下一轮 D3 输入或 D4/D7 状态机。
3. **P1 接口已完成，运行时接线待 main/D4/D6**: 已实现 `AssignmentValiditySummary`，包含 `plan_age`、`assignment_latency`、`cost_margin`、`stale_plan_version`、`duplicate_assignment_count`、`unassigned_high_threat_count`。
4. **P1**: 为 AirSim ComputerVision 5v5 建立 orchestrator 侧数据抽取器，把 actor/camera 状态转成 D3 dry-run records，并把 `AssignmentPlan`/binding 送入 D4/D5/D7/D6。
5. **P1/P2**: 增加 OR-Tools Min Cost Flow 可选后端。只有当 5v5 扩展到容量、备份资源、多窗口或分组约束时才需要。
6. **P1 接口已完成，日志接线待 main/D6**: 已定义 D3 到 D6 的统一 `AssignmentRecord` 日志格式和 `assignment_records_from_plan()` helper，避免 D6 从多个 plan 字段临时拼装指标。

## 4. 风险说明

- D3 当前核心 Hungarian 分配和迟滞逻辑已经可用于 5v5 离线仿真，但如果 integrated main 只提供原始位姿而不提供归一化 `covariance/window_cost/fov/conflict/feasibility`，分配仍会运行，但代价缺乏真实判别力。
- OR-Tools 未实现不是当前主线阻塞项；它只阻塞复杂容量/备份/多窗口约束实验。
- D5 terminal feedback helper 和 `AssignmentGuidanceBinding.binding_state` 不会自动阻止 planner 输出旧计划；需要 main 或 D4 根据 helper 的 `recommended_action`、binding 的 `hold/stale/revoked/reassigned` 状态执行 hold/replan/arbitration。
- AirSim dry-run adapter 不导入 AirSim，这是符合边界的；真正的 AirSim/Blocks runtime 接入应在 orchestrator 或独立 adapter 层完成。
