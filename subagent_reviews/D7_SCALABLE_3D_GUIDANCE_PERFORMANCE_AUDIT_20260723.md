# D7 三维导引固定输入性能审计

## 结论

`0d2da25` 到 `5263e2b` 的 nominal 200v200、10 秒、20-seed 整栈结果中，D7
`module.d7_guidance` 累计墙钟均值由 `3.637837 s` 增至 `3.858795 s`。逐 seed
百分比变化均值为 `+6.243%`，95% seed bootstrap 区间为
`[+2.954%, +9.825%]`。该差异在整栈样本上存在，但本次审计没有确认 D7 模块内核
发生真实性能回归。

两个提交的 86 个 D7 受控源文件完全相同，文件清单与 blob 摘要同为
`ac030cd9c5aecd8ebd92d2d82fec3719520a53fc4ae9699ed7ee34bc256d76a2`。
`scalable_3d_guidance.py` 的 Git blob 均为
`7b61b97c9a690e20368e470e06d522c6f07af717`。20 个 seed 的跨构建语义审计全部
通过，规范化在线总线载荷、D7 命令、模式、拒绝原因、计划血缘和物理状态一致。

固定 200 对、185 帧 replay 在两个工作树各执行 6 次。replay、37,000 条 pair 命令、
世界加速度数组、最终 200 个 pair 状态、模式和拒绝原因摘要全部严格一致。参考和候选
内核均值为 `1.837673 s` 和 `1.849179 s`，候选变化 `+0.626%`，95% bootstrap
区间为 `[-1.828%, +3.178%]`。区间包含零，且差值小于两组各自的运行变异。因此
整栈 `+6.243%` 不能归因为 D7 源码或可复现的 D7 内核热点。

本轮不修改位置比例导引、预计碰撞时间捷联视觉比例导航制导、视线滤波、预计碰撞
时间滤波、切换安全门、调用频率或任何阈值。没有实施局部优化。

## 源码和输入路径

D7 代码在两个提交间没有变化。main 的 `module_stack.py` 发生变化，但
`_guidance_inputs()`、D7 调用边界和 `command_batch()` 调用方式没有变化。相关差异是：

1. 每个阶段新增逐调用样本列表；
2. 每步诊断可计算阶段 P50、P95 和最大值；
3. D1、D2、D5 等其他模块存在独立性能改动。

阶段样本追加发生在当前 D7 计时停止后，诊断分位数也不直接计入
`module.d7_guidance`。这些工作仍会改变同一进程后续时刻的分配器状态、缓存占用、
处理器负载和执行顺序。它们可以形成连带效应，不能视为 D7 业务逻辑变化。

当前持久化 episode 没有保存 D7 每个 pair 的全部私有输入和滤波状态，无法从历史
输出反构完整输入数组。跨构建审计已经证明相同场景、真值、计划血缘和规范化在线
输出。固定 replay 用于进一步移除 main 输入组织和其他模块负载，但不替代未来完整
输入 sidecar。

## 固定 replay

固定 replay 使用以下条件：

- `200` 个 resource-track pair；
- `185` 个时刻，共 `37,000` 次 pair 调用；
- 固定 Python hash seed；
- OpenBLAS 和 OpenMP 均限制为单线程；
- 两个工作树固定在同一逻辑处理器；
- 按 `A-B-B-A` 顺序重复三轮，每个工作树 6 次；
- 中段样本、旧计划、失效航迹、陈旧航迹和末端视觉样本同时存在。

最终命令分布为：

## 成本分段

分段 profile 通过临时函数包装记录 Python 边界的排他墙钟。包装本身增加调用开销，
因此下表用于判断组成，不作为生产时延。所有类别合计和残差保持互斥。

| 类别 | 近似每 batch / ms | 占命令墙钟 | 说明 |
| --- | ---: | ---: | --- |
| 命令数据对象物化 | 2.884 | 23.74% | 命令字段、元数据、模式迁移和不可变输出对象 |
| 输入适配 | 1.775 | 14.61% | binding、GlobalTrack、D4 permission 和视觉输入规整 |
| 比例导引计算 | 1.770 | 14.58% | 中段位置/速度 PN 与末端纵向控制分量 |
| 航迹滤波 | 1.495 | 12.31% | 每 pair 航迹状态滤波与时间更新 |
| 计划、版本和安全门 | 0.437 | 3.60% | 当前计划、身份、D4、D5 和相机能力检查 |
| 视线和预计碰撞时间滤波 | 0.055 | 0.45% | 本 replay 中只有 420 次相关调用 |
| 批处理和内联几何残差 | 3.730 | 30.71% | 排序、循环、数组写入、几何和未单列辅助函数 |

两版的各类别占比近似重合。候选分段 trial 偶发整体变慢时，每个类别近似同比例变慢，
没有出现某一类别单独增加。该模式符合整进程执行速度变化，不符合新增局部热点。

固定 replay 的 37,000 个输入对象构造均值为 `0.233 s`，约
`1.260 ms/batch`。该数值只包括简化 DTO 构造，不包括 main 的 D2 查找、D4 permission
组织和 D5 pair 索引。最终 200 个 pair 状态诊断汇总均值为 `0.363 ms`，位于
`command_batch()` 之外。

命令对象物化和批处理残差是当前绝对成本最大的两个区域，但它们在两个提交中使用
相同代码，冻结输入没有显示稳定退化。本次不能仅凭占比对它们实施优化。

## 原因判断

| 假设 | 判断 | 依据 |
| --- | --- | --- |
| D7 源码变化 | 排除 | 86 个受控文件和关键 blob 完全相同 |
| D7 业务输入组成变化 | 未发现 | 20/20 跨构建语义一致；调用数和公开输出一致 |
| 可复现 D7 内核热点 | 未确认 | 固定 replay `+0.626%`，置信区间包含零 |
| CPU、缓存、调度连带效应 | 当前最合理 | 长尾明显、类别同比例变化、同进程其他负载已变化 |
| LOS/TTC 新增成本 | 排除 | 源码相同，固定 profile 只占约 0.45% |

“CPU、缓存、调度连带效应”是当前证据下的归因，不是硬件根因定位结果。现有日志没有
记录逐时刻处理器频率、温度、上下文切换和缓存计数器，不能进一步区分这些因素。

## 处置与开放项

1. 本次整栈差异登记为“D7 内核未确认回归，系统级运行环境差异待分段复核”，不登记为
   D7 算法缺陷或已关闭优化。
2. D7 核心代码保持不变。位置比例导引、预计碰撞时间视觉比例导航制导、LOS/TTC、
   切换安全门和调用频率均未修改。
3. main 后续应把 `_guidance_inputs()`、D4 permission 组织、D7 `command_batch()`、
   世界数组复制和 publication 分开计时，并避免在每个物理步重复计算全阶段分位数。
4. 若再次出现 D7 回归，应保存当前 pair 输入 sidecar 和必要状态快照，使用相同 replay
   在两个提交交错复测。只有命令、状态和拒绝原因严格相等且冻结差异区间排除零，才进入
   局部优化。
5. 本次视觉样本只有 120 条，不能用于评价真实末端视觉吞吐、AirSim 相机链路或
   `png_guidance_delivery` 性能。
