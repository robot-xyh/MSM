# D6 实现差距审计

审计范围：对照 `subagent_reviews/D6_EVALUATION_METRICS_REVIEW_AND_PLAN.md`、`subagent_reviews/MAIN_IMPLEMENTATION_GAP_AUDIT.md`、`C_UAS_MAINSTREAM_SOLUTIONS_AND_DIFFICULTIES.md` 和 `research_modules/d6_evaluation_metrics/` 现有代码/测试。本文只评估 D6 离线指标实现状态，不修改业务代码，不引入实时控制、火控参数、毁伤模型或自动处置逻辑。

## 总体结论

D6 当前已经落地一套轻量离线评估内核：统一记录 `TrackRecord`、`AssignmentRecord`、`EventRecord`、`LinkRecord`、`TerminalRecord`，并输出 `EpisodeMetrics`、CSV、Markdown 和 PNG 图表。核心标量指标如 `detection_probability`、`false_alarm_rate`、`track_rmse`、`id_switch_count`、`duplicate_assignment_count`、`failover_time`、`terminal_association_accuracy` 已有实现和单元测试。

与主流共识/开源方案相比，当前实现不是 Stone Soup、TrackEval、py-motmetrics 或 SCRIMMAGE 的直接适配层，而是先实现可解释的本地标量指标。OSPA/GOSPA、SIAP、MOTA/MOTP、HOTA、IDF1 仍停留在文档公式和后续扩展层面。AirSim 方面已实现 Blocks replay JSONL 的 D6-only 离线读取，但不是通用 AirSim recording 文件解析器。

与 Main 总审计对齐：D6 已完成 P0 的 D7 intercept adapter，可消费 `control_commands.csv` 和 `intercept_summary.json` 并把拦截成功类型、最小距离、拦截时间和 gate reject 纳入 `EpisodeMetrics`。本轮 P1 已补 D4 主动/被动降级细分聚合、D4 active-degradation CSV loader、D7 `guidance_records.csv` / `guidance_summaries.json` time-series 适配，以及按场景/故障/多视角状态分组的报告字段。后续剩余项主要是用真实 multi-seed episode 数据校准指标解释，而不是缺少基础接口。

## 关键缺失条件汇总

1. Stone Soup / TrackEval / py-motmetrics 接入缺少标准化帧级 truth-track 匹配表、外部依赖版本、门限配置和回归基准。
2. SCRIMMAGE 接入缺少实际输出样例、agent/resource/target ID 映射和 episode clock 对齐规则。
3. D7 P1 闭环指标已可从 `guidance_records.csv`、`guidance_summaries.json`、`control_commands.csv` 和 `intercept_summary.json` 计算；后续需要真实 episode 稳定输出这些文件。
4. 主动降级细分指标已经有 D6 默认聚合器；仍缺 main 持续写入的 D4 `degradation_mode`、`selected_coordinator`、`coverage_cell`、`review_label` 和窗口化事件流。
5. 真实 AirSim/Blocks 批量报告的分组图需要 episode metadata 保留场景因素、故障模式、通信条件和多视角一致状态。

## 建议执行顺序

1. 保持现有 P0 指标和 JSONL/Blocks replay 适配稳定，作为 main 集成回归基线。
2. 优先补 D4 decision event 的 main 日志接入，并用 D6 已有主动降级聚合器、D7 guidance time-series adapter 生成多 seed 报告。
3. 在 D1/D2/D5 的帧级 truth-track 输出稳定后，再接入 Stone Soup 或 py-motmetrics/TrackEval 做外部指标对照。
4. SCRIMMAGE 仅在 AirSim 多机规模或通信建模明显不足时启动，不建议现在作为 D6 主线依赖。
