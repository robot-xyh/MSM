# D7 比例导引与末端视觉 PNG 实现差距审计

**审计范围**：`subagent_reviews/D7_PROPORTIONAL_GUIDANCE_REVIEW_AND_PLAN.md`、`C_UAS_MAINSTREAM_SOLUTIONS_AND_DIFFICULTIES.md`、`research_modules/d7_proportional_guidance/`、`research_modules/d7_proportional_guidance/png_guidance_delivery/`、`research_modules/airsim_runtime/`、`research_modules/integrated_simulation/`、`research_modules/INTEGRATION_CONTRACT.md`。  
**边界**：本文只审计当前科研仿真、AirSim Blocks 闭环、离线记录和接口合同实现状态，不提出真实火控参数、毁伤模型、硬件部署或绕过人工授权的自动处置流程。

## 总体结论

D7 当前已经实现了可测试的离线二维经典 PN、合成视觉 LOS 末端模式、AirSim phase-1 dry-run 记录适配、SimpleFlight 受控 2v2 actor 拦截闭环、D3/D4/D5 terminal PNG 合同门控，以及从 `png_guidance_delivery` 抽取的轻量 TTC/视觉 PNG gate。`SimpleFlightPngGuidanceFilter` 已能根据 bbox 面积、检测置信度、LOS-rate 稳定性、视觉延迟、闭合速度和机动裕度决定是否允许进入视觉末端，并输出 SimpleFlight 速度命令。

主要差距集中在三处：

1. **P0 terminal PNG 合同已在 D7 API 和 AirSim controlled intercept 中实现，但完整 main bus 接入仍未闭环**。AirSim 受控拦截现在必须通过 D3 `AssignmentGuidanceBinding`、D4 permission/action/`terminal_consistent`、D5 `TerminalAssociation(decision_state=="locked")`、一致的 `assigned_global_track_id`/version 和 authorization 状态后，才允许进入 `SimpleFlightPngGuidanceFilter`；离线 `integrated_simulation` 仍按距离/时间直接切入 `vision_terminal`。
2. **Pure Pursuit 对照和显式 handoff/reject 状态已补 P1 基线，改进 PN/严格工程化视觉 PN 仍不完整**。经典 PN 已实现；`compute_pure_pursuit_command()` 和 `GuidanceConfig.guidance_law` 已可用于离线 PN/Pure Pursuit 对照；`GuidanceMode` 已加入 `handover_pending/hold/reacquire/abort_revoke`。FRPN/augmented/biased/true PN 尚未实现。
3. **PX4/MAVLink/YOLO+ByteTrack/OpenCV/KCF 等能力存在于 delivery 包或文档中，但未进入 main D7 主线**。当前主线明确选择 SimpleFlight `moveByVelocityZAsync` 和 AirSim `simGetDetections`，未直接调用 PX4 Offboard、MAVLink body-rate、YOLO/TensorRT 或 OpenCV 标定链路。

D7 回归测试已覆盖 D3/D4/D5 terminal PNG 合同和 AirSim controlled intercept 拦截门控：`python3 -m pytest research_modules/d7_proportional_guidance/tests`；`python3 -m pytest research_modules/airsim_runtime/tests/test_blocks_runtime.py -q`。

## 关键缺失条件汇总

1. **main 运行时 bus 接线**：P0 D7 gate 已消费 `AssignmentGuidanceBinding`、D4 permission/action/`terminal_consistent` 和 D5-shaped `TerminalAssociation`；下一步需要 main 在 integrated runner/5v5 AirSim 控制中提供真实 D3/D4/D5 流，替换当前 AirSim 2v2 的 simulation-only binding/association。
2. **D5 状态迁移和丢锁处理**：需要把 `locked/ambiguous/hold/reacquire`、friend conflict、锁定丢失、重捕获和检测超时事件接入 D7 pair state machine 与 D6 指标。
3. **严格视觉 PN 所需观测条件**：稳定 camera intrinsics/extrinsics、bbox timestamp、local track 连续性、LOS-rate 滤波、距离/闭合速度估计来源、视觉延迟和丢检策略。
4. **外部视觉/飞控依赖条件**：YOLO/ByteTrack 需要图像帧、权重、class id、Ultralytics/lap/lapx、性能预算；OpenCV/KCF 需要 contrib build；PX4/MAVLink 需要 SITL、pymavlink、Offboard 状态机、推力/坐标标定和安全流程。
5. **D6 指标消费条件**：D6 已可从 D7 CSV/summary/guidance time-series 读取 min range、time to intercept、collision/range success、abort reason、视觉 gate reject、terminal contract reject、D4/D5 和 plan/version 字段；后续需要真实 multi-seed episode 产生稳定输入，供分组报告校准。

## 建议执行顺序

1. **P0：D7 切换门控已完成并保持回归**。`hold/ambiguous/reacquire/friend_conflict` 不允许进入视觉末端；只有 D3/D4/D5 一致且授权有效时才调用 `SimpleFlightPngGuidanceFilter`。
2. **P1：把 P0 gate 接入 main runtime bus**。将真实 D3 `AssignmentGuidanceBinding`、D4 permission/action、D5 `TerminalAssociation`、撤销/重分配事件接入 integrated runner 和后续 5v5 AirSim 控制。
3. **P1 已完成基线：增强 D6 guidance/contract 报告**。D6 已能消费 `terminal_contract_reject_reason`、D4/D5 状态、plan/version，以及 `guidance_records.csv` / `guidance_summaries.json` 的 mode switch 和分组字段。
4. **P1 已完成基线：Pure Pursuit baseline**。离线 D7 已支持 PN vs Pure Pursuit 对照；严格 visual PN 回放仍需真实相机标定、local track 和距离/闭合速度估计。
5. **P2：保持 PX4/MAVLink/YOLO/OpenCV 在 delivery 或独立实验路径**。只有在 SimpleFlight + AirSim detect + D3/D4/D5 门控稳定后，再逐项迁移到 main 主线。
