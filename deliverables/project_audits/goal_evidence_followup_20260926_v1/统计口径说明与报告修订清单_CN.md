# 统计口径说明与报告修订清单

编制日期：2026年9月26日。适用范围为本次审计涉及的双光电报告回放、搜索回放、旧末端回放和中心误差矩阵。本文是审计说明及修订建议，不替代原实验记录；原Word、Markdown和清单均未修改。

## 一、基本处理原则

原计数、原取值和原汇总方式保持可追溯。解释不充分的，补充定义；原文与清单不一致的，列明差异及依据。任何重汇总都应另存版本，保留所有配置行，不能通过删去无输出、低结果或超时记录改善结果。

对每组结果至少说明：使用哪一批输入、哪一个统计窗口、分子和分母是什么、如何处理无输出、如何跨种子平均、是否设有处理期限。结论只适用于对应设置，不将旧单种子结果与后续误差矩阵混成同一试验。

## 二、无输出、不可计算和零计分

| 情形 | 比值含义 | 本次说明方法 |
| --- | --- | --- |
| 有输出且部分正确 | 正确数除以输出数 | 按保存计数解释精度 |
| 有输出但全部错误 | 输出数大于0，正确数为0 | 精度为0 |
| 没有输出关系 | 输出数为0，通常精度比值无定义 | 区分“精度不可计算”和实验约定的零计分 |
| 应评价目标存在，但没有正确覆盖 | 正确覆盖数为0，目标分母大于0 | 覆盖度为0 |
| 目标分母本身缺失或为0 | 不能按正常覆盖比值计算 | 登记缺失或不适用，不自动当作没有覆盖 |

中心误差矩阵960条记录中有246条没有输出关系，原CSV将精度和覆盖度都记为0。其精度均值包含这些零计分；双光电对无输出精度采用空值。两种表示不应直接混用。

零计分可以保留为该批次原统计政策，但需要写明。若另行统计“仅有输出批次的精度”，必须同时给出有输出批次数、无输出批次数及全批覆盖度，并另列新口径，不能替换原均值。本轮没有重算这种条件精度。

## 三、跨种子汇总

双光电报告的精度是先合并各场景正确数和输出数，再相除；中心误差矩阵是先计算各场景精度，再对10个种子取算术平均，零输出按原政策计0。两种方法分别回答“所有输出关系有多大比例正确”和“各次试验的原约定得分平均是多少”。

举例：两次普通记录分别为1条正确/1条输出、1条正确/9条输出。合并计数得到20%；对两次精度取均值得到55.56%。两者都可以正确计算，但不能不加说明地横向比较。

| 报告或批次 | 原汇总方式 | 应保留的样本说明 |
| --- | --- | --- |
| 双光电54组矩阵 | 精度采用合并计数比值；同组目标分母固定 | 每组5个seed；270条方法条件记录不是270个独立场景 |
| 搜索45条记录 | 同场景、误差档下5个种子的均值和最差值 | 三个输入路径只有两种运动文件哈希；0.8秒以后采用外推 |
| 中心误差960条记录 | 每配置10个seed均值，保存总体标准差和最小值 | 96组配置重复使用10个seed编号；不能说有960个独立场景 |
| 旧末端回放 | 同一保存观测作方法对照，部分计时重复5次 | 每规模一个试验种子；5次计时不等于5个随机场景 |

同一seed在不同方法下复用有利于配对比较，本身不是数据错误。需要防止的是将这些重复使用计入独立样本数量。

## 四、统计窗口和耗时

### 4.1 窗口

双光电报告只取最后窗口，360度为第6圈，180度为第12轮。上一批已核对270条最终记录与对应最后窗口一致。中心误差矩阵使用最后一帧仍有效的确认关系。全程曾经确认、最终仍然有效和累计发现是不同指标，不能互换。

### 4.2 超时

双光电有明确的1000毫秒期限，270条最终记录中135条超时。原记录保留其完成后的质量指标，超时案例按时覆盖度为0。报告已有这项说明，继续保留，不删掉超时后的质量，也不把该质量说成期限内结果。

中心误差矩阵没有足以重建同类期限判定的逐行字段。报告写明“未设置工程期限、全部计入质量统计”，但`metrics_contract.json`另写`timeout_included_as_failure=true`，两处不一致。应将这一元数据冲突登记为待更正，不能凭该布尔值推定每条结果已经通过或未通过时限。

### 4.3 缓存和计时范围

中心误差矩阵480条几何记录不复用投影缓存，480条图网络记录复用缓存。报告已有说明，保留即可，不将保存耗时用作同条件速度排名。

旧中心交接耗时包含关联、审计输出和绘图；机间无缓存计算、搜索规划耗时与之计时范围不同。它们可以各自说明本次运行时间，不能直接相减或合并成全流程耗时。

## 五、文件完整性与结果一致性

| 核查内容 | 合适的判断规则 | 不能作出的推论 |
| --- | --- | --- |
| 保存的原文件是否改变 | 按原SHA-256逐字节核对 | 哈希匹配不证明算法结论正确 |
| 配置、输入和源码身份 | 核对历史清单、快照及实际参数 | 当前HEAD或事后入库提交不能单独代表原执行状态 |
| 保存计数重汇总 | 整数计数准确对应，比值按已说明公式比较 | 算术核对不等于重新评分或回放 |
| 将来若开展重复运行 | 先约定完整记录键、计数、浮点量和可用性字段的比较方法 | 不能只选最终均值相近就说全部一致 |
| 耗时 | 单列运行条件和分布，不要求每次相同 | 含实测耗时的整份CSV不能承诺重跑后字节相同 |

建议的记录比较顺序是：先核对批次和配置身份，再查缺行及重复键，接着比较整数计数、可用性状态和质量数值，最后单列耗时。这个顺序用于通用记录核对，不构成开展新实验的授权。

对本轮保存比值的算术比较，可以沿用上一批`rel_tol=1e-9、abs_tol=1e-10`的数值检查规则；这不是对将来跨设备重运行承诺的误差范围。跨环境容差必须在比较前另行确定，不能看过差值后放宽。

中心清单中的“deterministic CSV equality”应改为分字段的比较说明。原CSV哈希仍保留，用于核对历史文件完整性，不回填耗时、不修改旧值。
