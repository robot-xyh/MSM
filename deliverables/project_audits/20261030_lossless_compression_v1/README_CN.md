# 仿真实验输出无损压缩与审查说明

## 1. 执行范围

2026年10月30日，对 `research_modules/` 下实验 `outputs/` 目录中的大型结构化数据进行逐文件无损压缩。

- 压缩对象：不小于64 KiB的 JSON、JSONL 和 CSV 数据文件；
- 压缩方式：`zstd-9`，每个原文件对应一个独立的 `.zst` 文件；
- 保留内容：Markdown、Word、PDF、图片、视频、NumPy数组、模型权重、配置、报告、摘要、索引、`manifest`以及Git跟踪文件；
- 目录结构：压缩文件保留在原目录，名称为“原文件名 + `.zst`”。

## 2. 完整性保护

每个文件均按以下顺序处理：

1. 计算原文件SHA-256；
2. 生成临时压缩文件；
3. 完整解压临时文件并重新计算SHA-256；
4. 核对解压后字节数和SHA-256；
5. 写入全局审查索引并同步到磁盘；
6. 校验通过后移除原始未压缩文件。

执行结束后，又对全部 `.zst` 文件执行了一次独立的 `zstd -t` 完整性检查，检查结果全部通过。

## 4. 索引文件

- `COMPRESSION_PLAN.csv`：压缩前冻结的完整计划；
- `ARCHIVE_CATALOG.tsv`：全局文件级审查索引；
- `COMPRESSION_SUMMARY.json`：本次压缩汇总；
- 各实验目录中的 `ARCHIVE_MANIFEST.json`：该实验可独立使用的文件索引。

`ARCHIVE_CATALOG.tsv`记录实验编号、原始路径、压缩路径、数据类型、压缩前后大小、节省空间、原文件SHA-256、压缩参数、校验时间和状态。

## 5. 审查与恢复

查看压缩文件内容，无需落盘解压：

```bash
zstdcat path/to/file.jsonl.zst | head
zstdcat path/to/file.csv.zst | head
```

检查单个压缩文件完整性：

```bash
zstd -t path/to/file.jsonl.zst
```

恢复单个文件并保留压缩包：

```bash
zstd -d -k path/to/file.jsonl.zst -o path/to/file.jsonl
```

恢复后可使用 `ARCHIVE_CATALOG.tsv` 中的 `sha256_original` 再次核对文件内容。

## 6. 使用注意事项

现有试验脚本如果直接读取原始 `.json`、`.jsonl` 或 `.csv` 路径，需要先恢复对应文件，或者在后续改造中增加流式读取 `.zst` 的能力。报告、配置和汇总指标仍可直接查看，不受本次压缩影响。
