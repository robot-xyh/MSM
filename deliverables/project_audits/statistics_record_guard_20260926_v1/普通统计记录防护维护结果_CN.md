## 一、已补充的检查

已有[边界检查](../goal_repro_stats_audit_20260926_v1/STATISTICS_BOUNDARY_TESTS.json)发现的是潜在风险，不是历史结果已经出错的证据。本批将普通记录检查接入现有报告证据审计工具，具体如下。

| 问题 | 现在的处理 | 使用条件 |
| --- | --- | --- |
| JSON同名字段被后一个值覆盖 | 发现重复字段立即报错，保留输入文件 | 默认检查，包括嵌套对象 |
| JSON含NaN、Infinity或超出有限浮点范围的数 | 拒绝读取，不替换成零或空值 | 默认检查 |
| CSV表头重复、缺列、多列或引号不完整 | 明确指出文件及数据行，停止读取 | 默认检查；正常引号内换行仍支持 |
| 相同记录重复导入 | 根据声明的完整键拒绝重复；相同内容也不静默去重 | 来源配置需提供record_contract |
| 同圈有两条冲突记录 | 若圈号属于完整键，两条记录会报冲突，不按先后顺序选一条 | 完整键必须包含该来源所需的全部维度 |
| 行数被当作不同种子数 | 分别报告record_count和distinct_seed_count；同种子的多圈记录不算新种子 | 配置group_by和seed_field |
| 缺失值被当作零 | 只接受显式声明可空的数值字段，分别计数有效与缺失；原值不变 | 配置numeric_fields和nullable_fields |
| 一个字段全部缺失 | 标记all_missing，不计算均值，不生成NaN | 同上；空表另行表示，不算全缺失记录 |
| 空值参与表格格式化 | 必须声明missing_text，才能显示“不可计算”等文字；否则明确报错 | 表格字段显示规则 |

检查器不推断完整键，也不决定统计分母、平均方式或样本独立性。未配置record_contract时，输出明确标为not_configured，只能说明已完成基本文件解析，不能声称重复记录检查已经通过。

标识字段只接受非空字符串或整数，同一字段不能混用两种类型。数值字段拒绝布尔值及非有限数。缺少字段与字段明确填null分别处理；允许空值不代表可以漏掉整列。检查过程不修改输入、不补值、不选取最后一圈，也不重算指标。

## 二、接入位置与使用方式

- [audit_record_validation.py](../tools/audit_record_validation.py)：严格JSON/CSV读取、完整键检查及有效值和种子计数。
- [audit_report_evidence.py](../tools/audit_report_evidence.py)：现有read_source入口调用上述检查；表格显示增加显式空值规则。
- [test_audit_record_validation.py](../tools/test_audit_record_validation.py)：人工构造记录的回归测试。

在审计配置的某个sources条目中，可按下面的普通示例声明字段。示例与实际实验无关，不能直接套用为所有实验的完整键。

```json
{
  "kind": "json",
  "path": "records.json",
  "selector": "records",
  "record_contract": {
    "unique_key": ["batch", "method", "seed", "round"],
    "group_by": ["batch", "method"],
    "seed_field": "seed",
    "numeric_fields": ["value"],
    "nullable_fields": ["value"]
  }
}
```

同一种子有两圈时，上例允许两条不同圈号记录，报告行数为2、不同种子数为1。同圈被重复导入则报错。若输入已经是每个种子一条的最终表，应按其真实结构声明完整键，而不是虚构圈号。

空值的显示规则示例为`{"field": "value", "format": ".1%", "missing_text": "不可计算"}`。原字段仍保留null，不能把显示文字理解成零分，也不能据此删去该条记录。

原有阶段审计配置和历史记录均未改写。本批只用人工样例验证接入，没有将现存实验结果批量重新导入或重新汇总。之后使用新的来源规则时，应另存配置版本并核对完整键，不能据此追认历史批次已经通过新检查。
