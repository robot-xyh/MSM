# 大模型辅助自动评估与报告生成方案

## 一、建设目的

当前系统能够从D1至D7、集成仿真和AirSim运行流程中产生航迹、分配、降级、视觉配准、导引和安全事件。随着场景数量和随机种子增加，人工逐份检查日志、整理指标和编写报告的工作量迅速增长，同一类失败也容易采用不同表述，影响跨批次比较。

本方案在D6确定性评估之后增加本地大模型分析层。它负责日志摘要、失败分类、跨实验比较、原因说明和中文报告草拟。原始日志、统计值和图表继续由程序生成，大模型没有修改原始记录、补写缺失指标或参与在线任务决策的权限。

## 二、边界

大模型处理以下工作：

- 将长日志压缩为结构化事件摘要；
- 对失败事件进行初步分类并给出证据；
- 比较不同算法、参数和随机种子的结果；
- 生成实验报告、问题清单和待复核事项；
- 根据已确认失败提出后续测试场景建议；
- 检查报告中的术语、状态和章节是否一致。

大模型不处理以下工作：

- 不生成或改写D1至D7原始日志；
- 不计算命中率、均方根误差、身份交换等正式指标；
- 不读取在线任务发布和飞行控制接口；
- 不创建、合并或修改全局目标编号；
- 不直接下发分配计划、降级动作和导引命令；
- 不把缺失数据推断成已经发生的事实。

“大模型生成日志”在本方案中指生成独立的分析标注日志，例如失败类别、证据引用和人工复核状态。该标注不能覆盖运行时原始日志。

## 三、总体架构

```text
D1-D7、main runtime和AirSim
        ↓
只追加原始日志
        ↓
D6数据清洗与确定性指标计算
        ↓
证据包生成器
        ↓
本地大模型分析服务
        ↓
结构化分析结果
        ↓
数值、证据和术语校验器
        ↓
Markdown/Word/PDF报告和复核清单
```

大模型服务部署在中心侧隔离工作站，通过只读目录或只读接口获取评估证据包。它只能写入独立报告目录，不能连接在线消息总线。

## 四、数据分层

### 原始记录层

原始记录由现有模块产生，包括：

- `TrackRecord`：航迹创建、确认、丢失、恢复和身份变化；
- `AssignmentRecord`：计划生成、版本变化、主备角色和重分配；
- `EventRecord`：中心失效、二级接管、通信退化和授权变化；
- `TerminalAssociation`：末端锁定、模糊、保持和重新捕获；
- D7导引状态、切换许可、控制摘要和拦截结果；
- 场景配置、随机种子、模型版本和运行环境摘要。

原始记录采用只追加方式保存。报告生成过程不得覆盖或重新排序原文件。

### 确定性指标层

D6继续计算正式指标，包括探测概率、虚警率、航迹均方根误差、航迹连续率、身份交换次数、重复分配次数、未分配高威胁目标数、故障转移时间、终端配准准确率、末端锁定时间和安全约束违规次数。

指标记录同时保存：

- 指标名称和中文说明；
- 数值、单位和可用性；
- 计算公式版本；
- 数据时间范围；
- 输入记录数量；
- 缺失原因；
- 对应证据文件和行号或事件编号。

大模型只能引用该层数值。

### 证据包层

证据包面向大模型，避免直接输入大体量原始日志。每个实验生成一个证据包：

```text
episode_manifest.json
metrics_summary.json
failure_candidates.jsonl
timeline_summary.json
configuration_diff.json
evidence_index.json
plot_manifest.json
```

证据包中的每条事实具有唯一编号，例如`METRIC-014`、`EVENT-028`和`PLOT-006`。大模型形成结论时必须引用这些编号。

### 分析标注层

大模型输出独立的分析记录：

```json
{
  "analysis_id": "ANALYSIS-0031",
  "episode_id": "episode_012",
  "category": "terminal_association",
  "finding": "末端锁定失败与连续三帧几何门限拒绝同时发生",
  "evidence_ids": ["EVENT-028", "METRIC-014"],
  "causality_state": "suspected",
  "confidence": 0.78,
  "requires_human_review": true,
  "model_version": "local-llm-v1"
}
```

当证据只能说明相关性时，`causality_state`必须标为“疑似”，不能写成确定原因。

## 五、自动评估功能

### 日志摘要

确定性程序先按时间窗口和模块归并事件。大模型将摘要整理为任务时间线：

```text
目标发现
→ 航迹确认
→ 初始分配
→ 中段导引
→ 视觉候选出现
→ 配准保持
→ 任务重规划或结束
```

摘要保留关键版本、时间戳、资源和全局目标编号。重复心跳、连续相同状态和高频控制采样由程序压缩，不送入大模型上下文。

### 失败分类

采用固定分类表：

| 一级类别 | 二级示例 |
|---|---|
| 探测 | 漏检、虚警、观测过期、覆盖不足 |
| 跟踪 | 航迹中断、身份交换、协方差发散 |
| 分配 | 高威胁未分配、重复分配、迟滞过强、资源不足 |
| 降级 | 接管超时、旧版本、联盟确认不足、通信分区 |
| 末端配准 | 几何门限拒绝、候选不唯一、友方冲突、目标框不稳定 |
| 导引 | 切换条件不足、机动余量不足、控制超时 |
| 系统 | 配置错误、日志缺失、接口版本不一致、运行中断 |

程序先根据明确事件码完成一级分类。大模型处理跨模块关系和二级原因说明。分类结果不能改变D6正式指标。

### 跨实验比较

大模型读取由程序计算的对比表，说明不同算法、随机种子和配置之间的差异。比较内容包括：

- 规则分配与学习增强分配；
- 不同迟滞门限；
- 不同目标和资源数量；
- 正常中心、二级接管和完全分布式场景；
- AirSim计算机视觉和SimpleFlight模式；
- 不同相机分辨率、视场和检测路径。

显著性检验、置信区间和均值计算由D6完成。大模型只解释已计算结果。

### 报告生成

报告生成器采用固定章节模板：

1. 试验目的；
2. 场景和配置；
3. 执行状态；
4. 指标结果；
5. 关键时间线；
6. 失败案例；
7. 结果判断；
8. 局限性；
9. 后续试验建议；
10. 证据索引。

表格和图表由程序插入。大模型生成正文说明，并在每个结论后保留证据编号。没有证据的判断写入“待复核事项”，不进入结果结论。

### 场景建议

大模型可根据已确认失败提出结构化场景建议，例如增加目标交叉、相机遮挡、通信丢包或资源失效。建议输出必须符合场景参数白名单，并由仿真配置校验器检查数量范围、时间关系和物理可达性。

## 六、本地模型和硬件

### 模型选择

首期采用具备中文能力的7B至14B开源权重语言模型，使用4比特或8比特量化。模型需要支持结构化JSON输出、较长上下文和本地推理。具体型号在部署前进行许可证、中文报告质量、数值复制准确率和显存占用测试。

32B级模型可作为复杂失败复核对照，不作为首期依赖。模型参数增加会提高显存、推理时间和运维成本，报告质量是否改善需要实测。

### 硬件建议

| 项目 | 基础配置 | 增强配置 |
|---|---|---|
| 图形处理器 | 24至32GB显存单卡 | 48GB显存或双卡 |
| 内存 | 128GB | 256GB |
| 本地存储 | 4TB固态存储 | 8TB以上固态与归档盘 |
| 模型规模 | 7B至14B量化模型 | 32B量化模型 |
| 预算 | 约2.5万至5万元 | 约6万至15万元 |

预算为工作站级估算，不含数据标注、软件开发和长期维护。所有模型、知识库、推理服务和报告数据保存在隔离网络内，不访问云端接口。

### 推理时间

建议性能范围：

- 单个失败事件分类不超过3秒；
- 单个实验摘要不超过10秒；
- 100个随机种子的聚合报告不超过5分钟；
- 结构化JSON输出校验不超过100毫秒；
- 模型超时后立即回退到确定性模板报告。

上述数值属于部署目标，需要在选定硬件和模型上实测。

## 七、报告可信性控制

### 数值锁定

提示词中不向模型开放自由计算。正式数字以占位符方式由程序填入，例如：

```text
身份交换次数：{{id_switch_count}}
终端锁定率：{{terminal_lock_rate}}
```

模型生成文字后，程序再次检查报告中出现的数字是否存在于证据包。无法匹配的数字标红并阻止报告发布。

### 证据绑定

每条结果判断至少引用一个指标或事件编号。引用不存在、范围不匹配或版本不一致时，报告进入人工复核状态。

### 两阶段生成

第一阶段模型只输出结构化分析JSON。第二阶段报告生成器根据已校验JSON和固定模板形成中文正文。该流程比直接让模型读取日志并生成完整报告更容易审计。

### 模型版本

每份报告保存：

- 模型名称和量化版本；
- 推理框架版本；
- 提示词模板版本；
- 知识库版本；
- 输入证据包校验值；
- 生成时间和随机参数；
- 原始模型输出。

模型升级后使用固定回归集重新验证，不能直接覆盖旧模型。

## 八、D6接口设计

建议在D6离线流程后增加四个独立组件：

| 组件 | 职责 |
|---|---|
| `EvidenceBuilder` | 从指标和事件生成证据包 |
| `LocalModelAdapter` | 调用本地语言模型并限制输入输出结构 |
| `AnalysisVerifier` | 校验数字、证据、术语和字段范围 |
| `ReportComposer` | 生成Markdown、Word和PDF报告 |

新增输出目录建议包括：

```text
evaluation_output/
  raw/
  metrics/
  evidence/
  annotations/
  reports/
  validation/
  model_manifest/
```

原始日志和正式指标与大模型产物分开保存。删除报告不会影响原始实验记录和D6重新计算。

## 九、实施步骤

### 第一阶段 证据包和模板报告

冻结D6指标名称、单位、可用性和证据编号。建立固定Markdown模板，不接入大模型。验证同一输入能够重复生成相同表格、图表和数字。

### 第二阶段 日志摘要和失败分类

接入本地7B至14B模型。先处理单个实验和已知失败类型，输出结构化分析JSON。使用人工标注案例评估分类一致性和证据引用准确性。

### 第三阶段 批量比较和中文报告

支持多随机种子、不同算法和不同配置的聚合报告。增加数值锁定、证据校验、模型版本和人工复核状态。

### 第四阶段 场景建议

根据已确认失败生成下一轮结构化测试建议。建议经过配置白名单和物理约束校验后，才能进入main调度队列。

### 第五阶段 长期回归

建立固定评估集，覆盖D1至D7典型成功和失败案例。模型、提示词、指标公式或日志结构变化后自动运行回归，比较分类结果、证据引用和报告差异。

## 十、验收指标

以下为建议验收口径：

| 指标 | 建议要求 |
|---|---|
| 原始日志改写次数 | 0 |
| 正式指标由大模型计算的数量 | 0 |
| 报告数字与D6指标一致率 | 100% |
| 结果结论证据引用覆盖率 | 100% |
| 不存在证据的确定性结论 | 0 |
| 结构化输出解析成功率 | 不低于99% |
| 已知失败分类一致性 | 在人工标注集上单独验收 |
| 单实验摘要时间 | 建议不超过10秒 |
| 批量报告时间 | 建议不超过5分钟 |
| 在线任务和控制接口访问次数 | 0 |

失败分类准确率不预设固定值，需先建立具有代表性的人工标注集，再根据类别不平衡情况确定宏平均F1值门限。

## 十一、风险与处理

### 日志结构不一致

D1至D7字段、单位和状态名称变化会影响证据包。处理方法是冻结模式版本，旧模式通过确定性适配器转换，大模型不承担字段兼容。

### 上下文过长

大模型不读取完整高频日志。程序先按事件、时间窗和模块分层摘要，只把与当前问题相关的证据送入模型。

### 虚构和错误归因

所有结论必须引用证据。相关性和因果性分开标记。大模型不能确认原因时输出“证据不足”。

### 模型输出波动

推理使用固定模型、固定模板和低随机度，保存原始输出。正式指标和图表保持确定性，文字差异不影响计算结果。

### 本地算力竞争

报告、视觉模型训练和AirSim仿真可能争用同一图形处理器。任务调度器应错开模型批处理和实时仿真，必要时将D6报告工作站与视觉训练工作站分离。

### 数据和模型安全

模型服务禁止联网，知识库只加载批准文档。模型文件、提示词和证据包采用校验和管理。未经验证的模型不能替换当前版本。

## 十二、阶段结论

D6离线评估是本地大模型最适合首先接入的位置。数据已经结构化，时延要求宽松，模型异常不会影响在线任务。首期建设重点是证据包、数值锁定、失败分类和固定模板报告。场景建议在报告链路稳定后实施。

该方案降低批量实验的人工整理工作量，并统一失败分类和报告口径。正式指标、任务结论和原始证据仍由确定性程序管理，大模型产物始终保持可删除、可复核和可回退。
