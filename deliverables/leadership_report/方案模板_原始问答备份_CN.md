# 协同搜索原始问答备份

本文件从会话记录恢复，用于保留正式补充素材文末曾附带的原始问答。正文内容未重新改写。

## 问题一  协同搜索有哪些算法，包括成熟方法和学术前沿方法

有。协同搜索通常不是单一算法，而是四类算法组合：**区域划分、搜索任务分配、航迹与云台规划、搜索结果更新**。

**工程成熟方法**

| 方法 | 主要作用 | 成熟度 | 适用情况 | 主要限制 |
|---|---|---:|---|---|
| 固定扇区、平行航线、往复式扫描 | 按预定路线覆盖责任区 | 高 | 目标分布未知、通信较差 | 不利用实时目标概率，重复搜索较多 |
| Voronoi分区与Lloyd覆盖 | 按无人机位置动态划分就近责任区 | 高 | 多机覆盖连续区域 | 只强调覆盖距离，难直接处理目标威胁度 |
| DARP均衡区域划分 | 将搜索网格均衡分给多架无人机 | 较高 | 搜索面积规则、需要控制工作量均衡 | 动态目标和三维空域适配需要改造 |
| 贝叶斯概率地图 | 根据“发现、未发现”持续更新各区域存在目标的概率 | 高 | 中心只能提供粗略位置或概率范围 | 检测概率模型不准时会产生错误收敛 |
| 下一最佳视角 | 选择下一次最有可能发现或确认目标的观察位置 | 较高 | 云台视场窄、需要主动调整观察方向 | 多机联合优化计算量较大 |
| 滚动时域规划 | 每隔一段时间重新计算后续搜索动作 | 高 | 目标运动、环境和任务不断变化 | 规划窗口过短容易频繁改变任务 |
| 匈牙利算法 | 将无人机与当前搜索单元一一分配 | 高 | 单周期、一机一个搜索任务 | 不适合直接安排连续多步路线 |
| 最小费用流、车辆路径规划 | 安排一架无人机连续搜索多个单元 | 高 | 多搜索点、航时和容量受限 | 大规模动态重算成本增加 |
| 拍卖算法、CBBA | 无中心条件下通过报价形成任务分配 | 较高 | 通信不稳定或中心失效 | 可能收敛较慢，多机共同执行一个任务较复杂 |
| 搜索状态机 | 管理搜索、发现、复核、跟踪和重捕获 | 高 | 工程系统主流程 | 规则和阈值需要实测标定 |

其中最稳妥的工程组合是：

```text
粗略目标范围
→ 建立三维概率地图
→ 划分相机可观察的搜索单元
→ 匈牙利或最小费用流分配
→ 无人机飞行与云台联合扫描
→ 根据发现和未发现结果更新概率
→ 滚动重新分配
```

**研究型方法**

1. **部分可观测马尔可夫决策过程**

   把目标真实位置视为未知状态，以概率分布表示当前判断。算法根据历史观察选择下一处搜索位置。POMCP、SARSOP等求解器适合小规模验证，但多架无人机、大量搜索单元会出现计算量快速增长。

2. **信息增益搜索**

   每个候选观察动作都计算其预计减少多少不确定性，然后选择信息收益最大的方向。它比单纯选择“概率最高区域”更合理，因为还会考虑视角、距离、遮挡和不同无人机观察结果的互补性。

3. **遍历控制**

   让无人机在一段时间内访问各区域的频率与目标概率分布成比例。高概率区域访问更频繁，低概率区域仍保留一定检查频率，适合持续搜索和目标可能重新出现的场景。

4. **随机有限集多目标搜索**

   使用概率假设密度、多伯努利或广义标签多伯努利模型，同时估计目标数量、位置和存在概率，再控制传感器寻找最有价值的观察方向。理论完整，但计算和参数标定要求较高。

5. **多智能体强化学习**

   MAPPO、HAPPO、QMIX、MADDPG等算法可以学习区域选择、协同补扫、角色分工和资源增援。它适合目标机动规律复杂、规则难以完整描述的场景。主要问题是训练样本量大，对训练场景之外的情况缺少稳定保证。

**学术前沿方向**

| 方向 | 主要思路 | 潜在作用 | 当前风险 |
|---|---|---|---|
| 图神经网络与强化学习 | 将无人机、搜索单元和目标线索组成图 | 支持无人机数量变化和局部通信 | 图构造和训练分布决定性能 |
| 多智能体Transformer | 用注意力处理长时间搜索记录和多机关系 | 适合复杂历史信息和大规模协同 | 推理开销和可解释性较差 |
| 学习型通信 | 自动学习何时通信、向谁通信、发送什么摘要 | 降低带宽并减少无效消息 | 仿真通信模型与真实数据链差异明显 |
| 可微分匹配与最优传输 | 使用Sinkhorn等方法学习软分配，再转成确定任务 | 可处理模糊线索和大规模候选 | 必须增加唯一性和安全约束 |
| 世界模型与模型化强化学习 | 学习目标运动和搜索结果变化，再在内部预测未来 | 可减少真实试验样本需求 | 模型预测偏差会累积 |
| 离线强化学习 | 使用既有仿真和试验日志训练策略 | 不需要在线探索危险动作 | 日志覆盖不足时容易产生错误策略 |
| 安全强化学习 | 强化学习提出搜索动作，规则检查飞行安全和任务冲突 | 兼顾策略适应性与安全约束 | 安全边界和失效回退仍需人工定义 |
| 视觉基础模型辅助搜索 | 离线生成目标特征、伪标签和困难场景 | 可改善复杂背景下的目标发现 | 小目标、红外和机载实时部署仍受限制 |

**对当前项目的建议**

当前“中心提供粗概率范围，多架带云台拦截无人机自行搜索”的场景，建议采用混合方案：

```text
贝叶斯三维概率地图
→ 按相机视场生成动态搜索单元
→ 规则计算基础收益
→ 匈牙利算法完成当前周期分配
→ 最小费用流安排后续搜索顺序
→ 滚动更新和重新规划
→ 通信异常时采用拍卖或CBBA
→ 图神经网络编码多机关系
→ MAPPO只修正搜索优先级、角色和补扫策略
→ 确定性规则检查航程、视场、云台限位、碰撞和任务冲突
```

强化学习适合决定“**优先搜索哪里、谁负责补扫、何时复核**”，暂不建议直接输出飞行舵量或云台电机指令。这样既能利用学习算法处理复杂目标分布，又能保留工程上可检查、可回退的安全边界。

## 问题二  哪些算法适用于当前场景

结合当前场景：

```text
中心双光电给出目标粗概率区域
→ 多架带云台拦截无人机进入区域
→ 无人机之间可以通信
→ 各机视场窄，可能只看到少量目标
→ 发现后进行复核、配准和任务分配
```

最适合采用以下组合。

**一、推荐主线**

1. **三维贝叶斯概率地图**

把中心提供的粗略位置和不确定范围离散成三维搜索单元。每个单元保存目标存在概率、最后观察时间和观察质量。

无人机检查某单元后：

- 发现目标：提高该区域及目标预测方向的概率；
- 未发现目标：根据相机探测能力降低概率；
- 观察距离过远或目标像素不足：只小幅降低，不能直接判定没有目标；
- 长时间未检查：概率逐渐恢复，防止高速目标穿过已搜索区域。

这是当前方案最重要的搜索状态表示。

2. **视场约束的动态区域划分**

不按固定地理网格简单切分，而是根据相机视场、距离和目标预测方向生成搜索单元。

近距离窄视场使用较小单元，远距离使用较大单元；目标可能经过的方向提高空间分辨率。这样能够把“粗略概率区域”转换成云台实际可以观察的任务。

3. **信息收益驱动的搜索优先级**

为无人机 \(i\) 搜索单元 \(j\) 计算收益：

\[
S_{ij}=P_jP_{D,ij}I_{ij}
-\lambda_1T_{ij}
-\lambda_2O_{ij}
-\lambda_3R_{ij}
\]

其中：

- \(P_j\)：目标位于该单元的概率；
- \(P_{D,ij}\)：该无人机在当前距离和视角下的发现概率；
- \(I_{ij}\)：预计减少的不确定性；
- \(T_{ij}\)：到达和云台转动时间；
- \(O_{ij}\)：与其他无人机重复搜索的程度；
- \(R_{ij}\)：通信、续航和机动风险。

这种评分比“永远搜索概率最高处”更适合多机协同。

4. **滚动匈牙利分配**

每隔固定周期，把无人机和当前最有价值的搜索单元组成代价矩阵，用匈牙利算法完成一一分配。

它适合当前系统，因为：

- 算法成熟、结果稳定；
- 可以处理无人机和搜索单元数量不相等；
- 便于加入航程、云台角度、重复观察等代价；
- 每个周期重新计算，可以跟随目标概率区域移动。

如果每架无人机一次需要安排多个连续搜索单元，再增加**最小费用流或带收益路径规划**，不能只使用一次匈牙利分配。

5. **下一最佳视角**

无人机到达责任区域后，从多个候选观察位置和云台方向中选择预计发现概率最高的一个。

主要考虑：

- 目标预测方向；
- 成像像素是否达到识别要求；
- 云台转动时间；
- 与其他无人机视场的互补程度；
- 是否需要从不同方向复核同一疑似目标。

下一最佳视角适合控制“接下来向哪里看”，匈牙利算法负责决定“谁负责看”。

6. **搜索状态机**

建议保留明确的工程状态：

```text
进入搜索区域
→ 扫描
→ 疑似发现
→ 第二视角复核
→ 建立局部航迹
→ 多机配准
→ 转入持续跟踪
→ 丢失后局部重捕获
→ 重捕获失败后返回概率地图
```

这部分使用规则实现更可靠，不适合完全交给强化学习。

**二、适合作为增强方案**

- **最小费用流**：为每架无人机规划多个连续搜索单元。
- **拍卖或CBBA**：中心通信失效时，由无人机之间协商任务。
- **多假设跟踪**：多个疑似目标交叉或短时丢失时保留多个解释。
- **遍历控制**：需要长时间反复监视同一区域时使用。
- **图神经网络**：编码无人机、搜索单元和目标线索之间的关系，适合数量变化和较大规模。
- **MAPPO强化学习**：修正搜索优先级、补扫关系和无人机角色，建议先以影子模式运行。

强化学习可以输出：

```text
搜索单元优先级修正值
补扫或复核建议
搜索、跟踪、增援角色
云台扫描模式
```

最终任务分配仍由匈牙利、最小费用流和安全规则完成。

**三、暂不适合作为主线**

- 完整多机部分可观测马尔可夫决策过程：大规模计算量过高。
- 端到端多智能体强化学习：训练外场景的稳定性难保证。
- 只用Voronoi分区：不能充分利用目标概率、相机像素和机动方向。
- 只用固定往复式扫描：搜索效率低，容易重复观察。
- 图神经网络直接输出最终飞行控制：缺少确定性安全约束。
- 纯CBBA作为正常主线：中心可用时效率通常不如中心化滚动分配。

因此，当前最合适的主线是：

```text
三维贝叶斯概率地图
+ 视场约束搜索单元
+ 信息收益评分
+ 滚动匈牙利分配
+ 下一最佳视角
+ 规则状态机
```

后续再增加“图神经网络编码关系、强化学习修正优先级、CBBA通信失效保底”。
