# D4 v6 转移动作学习开发候选

## 结论

D4 已建立版本隔离的 v6 转移动作学习候选。候选解决了 v4 中“边是否激活”和“转移
数量”共用同一连续输出造成的训练冲突，并补充有向边排序、正边数量、投影后动作和失败
原因审计。现有 TRAIN/VALIDATION 可以训练出非退化 checkpoint，构建过程可重复。

v6 尚未达到准入条件。TRAIN/VALIDATION 的投影后正动作命中为 `58/60` 和 `13/15`，
与冻结 v4 相同；负类基线动作保持为 `255/290` 和 `55/60`，低于 v4 的 `276/290`
和 `58/60`。负类按“与 R0 无可执行差异”定义，其中包含 12 个 R0 自身带转移的 TRAIN
帧。v6 只保留为未注册、仅影子开发候选。固定 0.60 置信门不降低，规则回退强制，
生产、分配、降级、接管、联盟、控制、物理、D3 和 D7 权限全部关闭。

## 数据边界

训练输入继续绑定冻结 v4 数据：

- 数据 SHA-256：`b31fc43f3d3cff34ee53f2b2c33ece0b06d7624e46e26a36c4aa834135e7fb8c`；
- 切分 SHA-256：`c212fe9b48e9908fd4d47488711724ed361429cf9df29667ac32c3e88d094619`；
- TRAIN：350 帧，只用于拟合和 TRAIN 派生权重；
- VALIDATION：75 帧，只用于 checkpoint 选择；
- TEST payload：读取 0，拟合 0；
- 正式 holdout seed 1000-1019：读取 0；
- v5 来源独立评价 seed 3008-3039：读取 0。

构建器显式拒绝载入正式 holdout 和 v5 来源独立评价 seed。当前 external test 已经被
既有评价读取过，不能用于 v6 调参或候选选择。

## 根因

TRAIN 有 60 个安全正动作和 290 个负动作。边标签中有 72 条正转移边和 3,848 条零边，
正边占 1.84%，零边与正边之比为 53.444。冻结 v4 将非零边权重上限设为 32，正边有效
质量为 2,304，零边有效质量为 3,848，零边仍高 1.670 倍。

v4 使用单个连续 `edge_mean` 同时表达三个决策：

1. 该边是否激活；
2. 转移方向是否正确；
3. 转移资源数量。

均方误差可以约束连续值，但没有独立的边激活分类、帧内有向边排序和转移数量损失。
首次 v6 原型把激活损失直接施加在同一连续值上，正确边方向已被激活，但目标转移数量
从 1 被推高到 3，完整有向边签名命中仍为 0。该原型按失败关闭处理，没有生成候选。

## 算法

v6 保留共享图消息传递和节点动作头，在候选内部增加独立边激活头。边数量头继续生成
与现有 `GraphPolicyOutput.edge_mean` 兼容的连续值。推理时只有激活得分不低于零的边
进入数量解码，未激活边固定输出无转移值。

训练损失为：

\[
L =
w_s L_{\text{node}}
+ L_{\text{activate}}
+0.25L_{\text{magnitude}}
+0.50L_{\text{direction}}
+0.25L_{\text{count}} .
\]

其中：

- `L_activate` 使用 TRAIN 派生的正边权重 53.444；
- `L_direction` 要求同一帧正确有向边得分高于零边，固定间隔为 0.25；
- `L_magnitude` 只拟合正边连续数量；
- `L_count` 比较可微转移资源数与目标资源数；
- 帧级正样本权重 4.833 只作用于节点动作，避免与正边权重重复放大。

checkpoint 先检查投影后行为，再比较可微损失。排序依次考察非退化动作、投影后 exact
正动作、正确 source-target 有向边、负类基线动作保持、no-transfer 偏置、投影拒绝、
不变量失败、TRAIN 权重下的 VALIDATION loss 和较早 epoch。低均方误差的全
no-transfer 模型不能胜出。

## 结果

固定随机种子为 `20260730`，隐藏维度 24，消息传递 2 轮，最多 240 epoch。最佳
checkpoint 为 epoch 119，提前停止于 epoch 164。

| 指标 | TRAIN | VALIDATION |
| --- | ---: | ---: |
| 帧数 | 350 | 75 |
| 正动作数 | 60 | 15 |
| 负动作数 | 290 | 60 |
| 投影后 exact 正动作 | 58 | 13 |
| 正确有向转移边 | 58 | 13 |
| 负类 exact 基线动作保持 | 255 | 55 |
| 正动作 no-transfer 偏置 | 0.033333 | 0.133333 |
| 投影拒绝 | 0 | 0 |
| 可执行差异 | 93 | 20 |

v6 消除了首次原型的数量 1 推高到 3 问题，并保持零投影拒绝。内部正动作命中没有超过
v4，负类误转移增加。当前损失仍需在新的训练版本中改善负类保持和困难负类区分。

## 可重复性

同一输入和固定配置在两个独立目录完成重复构建，逐文件比较无差异：

- 候选 manifest 内容 SHA-256：
  `f40064e7b25d4b9d908be466b12b5e50447b31b251e8ba0b308b1e5a6466a83f`；
- 训练审计内容 SHA-256：
  `ebc1334dcc2e7f9ed0cbe87354555021a1bb6d90a49bb7bcee7594a3364bee9a`；
- 模型参数内容 SHA-256：
  `c09d1719c550c4dd35a72d1ea5b1538e198811045d61e9e72f81fac899dba9e6`；
- 规范状态文件 SHA-256：
  `e92ea3aa55fd8f13d180e37aa15154e3e5fe58ab4611805805ba46bcd07b6ea8`。

v6 使用候选专属的规范张量流保存参数。该格式只用于开发制品，通用运行时没有注册
加载器，避免未准入候选进入在线路径。

## 验证

v6 专项测试 12/12 通过。测试覆盖纯负例 no-transfer、正边梯度强于零边、错误方向和
错误边不计 exact hit、全 no-transfer checkpoint 拒绝、TRAIN-only 权重、禁用 seed
拒绝、重复 bundle/hash 和权限关闭。

D4 全量测试为 855/855 通过。唯一警告是既有 Matplotlib `Axes3D` 环境问题。新增和
修改 Python 文件通过语法检查。

## 未闭合条件

1. v6 actor 尚未冻结，也没有新的置信校准器。
2. 来源独立正类召回仍未建立。seed 3008-3039 已用于旧候选评价，不能复用。
3. 新训练数据需要增加安全 transfer 正动作、困难负类、有向边和区域拓扑多样性。
4. 新候选冻结后，需要使用全新且未见的 development 数据盲审；正类分母充分前不读取
   正式 holdout。
5. runtime preflight、D3 successor、D7 权限、AirSim 和物理收益均不启动。
