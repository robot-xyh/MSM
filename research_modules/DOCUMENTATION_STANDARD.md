# 研究模块文档结构规范

本文档定义 D1-D6 离线科研模块的统一文档入口。各模块可以保留已有历史目录，但新增或补充文档应优先遵循本规范，避免报告入口分散。

## 统一目录

每个模块建议保持以下结构：

```text
<module>/
  README.md
  PLAN.md
  docs/
    ALGORITHM_AND_IMPLEMENTATION.md
    EXPERIMENT_REPORT.md              # 如已有历史报告，可用索引指向原位置
    AIRSIM_INTEGRATION_PLAN.md        # 如已有历史计划，可用索引指向原位置
  src/ 或 <package>/
  tests/
  scripts/ 或 simulations/
```

已有 `reports/`、`results/`、`outputs/` 目录可以继续存放历史报告、生成图表和批量实验输出。不要为了整理目录破坏现有 Markdown 图片链接或测试脚本路径。

## 详细算法文档模板

`docs/ALGORITHM_AND_IMPLEMENTATION.md` 使用中文编写，并包含以下章节：

1. 模块定位与边界。
2. 输入、输出与上/下游依赖。
3. 核心算法原理。
4. 数学模型与关键变量。
5. 主要实施流程。
6. 数据结构与接口。
7. 参数、门限与调参建议。
8. 仿真验证与评估指标。
9. 与其他模块的集成关系。
10. 局限性与后续工作。

## 共同工程约束

- 所有观测和航迹应保留时间戳、坐标系、协方差和置信度语义。
- `global_track_id` 由全局航迹维护方持有，终端模块不得重写。
- 分配计划必须版本化，过期版本应被拒绝。
- 终端状态使用 `locked/ambiguous/hold/reacquire`。
- 降级链路按中心 C2、二级侦察/备份节点、完全分布式协商的顺序描述。

## 安全边界

本文档集只服务离线科研仿真、日志回放和算法评估。不得加入真实飞控接口、硬件驱动、实时通信链路、火控参数、毁伤模型、自动处置逻辑或绕过人工授权的流程。
