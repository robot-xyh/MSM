# 增强几何路线第二版结果分析

## 结论

`enhanced-geometry-online-v2`完成了第二版快照适配、9回合预检、30-seed标定冻结和20-seed保留测试。数据隔离、输入指纹、冻结指纹和超时失败关闭均按协议执行。

路线没有形成可用的100目标在线配准能力。验证集F1为0.004654，33组选中关系中只有15组正确；冻结接受只表示F1、正确关系数和选中关系数均大于0。保留测试宏F1为0，95分位端到端时延为10268.93毫秒，1000毫秒时限满足率为0.1667。该结果必须判定为测试未通过。

## 版本边界

本报告只分析：

- 输出根目录：`dual_optical_online_benchmark/outputs/formal_v2_24_6_20/`
- 路线版本：`enhanced-geometry-online-v2`
- 预检种子：`20270001-20270003`
- 标定种子：`20270101-20270130`
- 保留测试种子：`20270201-20270220`

旧`formal_24_6_20/`对应第一版路线。第一版验证和测试均为零匹配，测试95分位时延为201.73毫秒，主要失败点是共面门控清空候选。第二版使用新的共享跟踪器和协方差快照，验证集出现少量正确关系，但保留测试受到严重超时阻断。两个版本的失败现象不同，不能合并指标或把第二版冻结状态解释成对第一版结果的修复验收。

## 试验协议

第二版统一协议固定100个3米目标，速度50米每秒，其中50个沿光轴方向来袭，50个与光轴方向相差负30度。两台光电节点间距2千米，扫描周期2秒，每圈连续转动360度；单个episode运行12秒，形成6个逐圈发布时刻。

仿真加入云台固定偏差和逐帧抖动，均方根分别为0.4毫弧度和0.3毫弧度；两项合成量级约0.5毫弧度。探测输入分为轻、中、重三档漏检和虚警。每次在线发布的端到端时限为1000毫秒，超时结果按失败处理，不允许事后回填。

AirSim真实身份和Actor名称不进入在线快照。身份标签在每条路线完成当前圈发布后才打开，用于离线计算精确率、召回率、F1、错配和重复身份。

## 第二版实施

第二版入口读取统一匿名因果快照。除方位、俯仰和时间戳外，快照携带角速度、测量协方差、四维运动状态及其协方差、相机姿态协方差、轨迹状态、最近命中窗口和共享跟踪器指纹。路线将角度和协方差统一转换为弧度制，旧第一版快照仅走保守兼容路径。

路线按以下顺序处理每圈快照：

1. 校验协议指纹、输入指纹、共享跟踪器指纹和冻结参数指纹；任何不一致均拒绝执行。
2. 只保留达到最少扫描圈要求的两侧局部轨迹，按共同时间对齐轨迹状态。
3. 使用归一化共面性残差和协方差卡方门筛除几何不相容的轨迹对。
4. 对保留候选执行多时刻恒速拟合，计算几何和运动代价。
5. 使用带未匹配项的匈牙利算法形成一一关系，并保留最多3个全局假设。
6. 在最近3圈内至少命中2圈、累计支持度达到0.7后确认关系；歧义和矛盾关系保持待确认或失败关闭。

该路线是确定性算法。训练快照用于输入哈希审计，不训练神经网络或其他学习系数。参数从预先定义的候选网格中按验证集结果选择，保留测试标签不参与选择。

## 预检

预检先验证共享单站跟踪器，避免在两侧均没有稳定轨迹时启动正式标定。3个seed分别运行理想、姿态误差和完整干扰场景，共9个回合。预检阶段没有读取保留测试集。

首次候选配置采用10米运动初始化残差门和3个全局假设，完整干扰场景的中位轨迹纯度为0.8452，低于0.85门限，因此失败关闭。离线比较预先列出的候选后，选定3米运动初始化残差门和单个全局假设。最终预检结果如下。

| 场景 | 回合数 | 平均共同确认成轨率 | 中位轨迹纯度 | 预检门限 | 结果 |
| --- | ---: | ---: | ---: | --- | --- |
| 理想 | 3 | 0.7767 | 1.0000 | 成轨率不低于0.70，纯度不低于0.85 | 通过 |
| 姿态误差 | 3 | 0.7433 | 0.9167 | 成轨率不低于0.65，纯度不低于0.85 | 通过 |
| 完整干扰 | 3 | 0.6833 | 0.8889 | 成轨率不低于0.50，纯度不低于0.85 | 通过 |

共同确认成轨率使用离线身份判断两台相机是否都形成同一真实目标的已确认局部轨迹。标签在跟踪完成后打开，只用于诊断。该指标不表示两侧局部轨迹已经被增强几何路线正确关联。

预检期间AirSim在reset后延迟销毁Actor，造成一次同名Actor异常。运行恢复后补齐第9个回合，最终矩阵保持3个seed乘3类场景。该运行事实不改变指标口径。

## 标定与冻结

标定阶段使用24个训练seed和6个验证seed。每个seed包含三档干扰和6圈快照，训练部分432份，验证部分108份，共540份。增强路线检查了64组候选配置，选择策略依次比较验证确认关系F1、错误和重复身份、处理时延。

冻结配置的主要参数为：最少轨迹圈数2，最少对齐样本2，共面残差中位数门限0.5毫弧度，协方差门置信度0.995，未匹配代价1.5，最多3个全局假设，三圈内命中两次并达到0.7支持度后确认。

| 验证指标 | 结果 |
| --- | ---: |
| 选中关系数 | 33 |
| 正确关系数 | 15 |
| 错误关系数 | 18 |
| 精确率 | 0.4545 |
| 召回率 | 0.002339 |
| F1 | 0.004654 |
| 正确候选机会数 | 6413 |
| 保留正确候选数 | 1315 |
| 正确候选保留率 | 0.2051 |

冻结验收要求F1、正确关系数、选中关系数、正确候选机会数和保留正确候选数均大于0。以上条件全部满足，因此生成本路线冻结清单，并进入三路线联合冻结。冻结清单同时记录测试快照打开次数和测试标签打开次数均为0。

这套要求解决了第一版“验证结果全为0仍可冻结”的流程缺口，但门限只排除了完全没有关联能力的配置。验证F1为0.004654，远低于可用性能要求。冻结通过应表述为“通过非零能力门控”，不能表述为“验证性能通过”或“算法可用”。

## 保留测试

保留测试使用20个未见seed。每个seed包含轻、中、重三档干扰，每档6圈，共形成360次在线发布。三条路线读取相同快照，输入指纹校验通过；增强路线只使用冻结后的共享跟踪器和参数。

| 测试指标 | 结果 |
| --- | ---: |
| 发布次数 | 360 |
| 正确匹配数 | 0 |
| 宏平均精确率 | 0 |
| 宏平均召回率 | 0 |
| 宏平均F1 | 0 |
| 错误匹配数 | 0 |
| 重复身份数 | 0 |
| 计算可用率 | 0.1667 |
| 1000毫秒时限满足率 | 0.1667 |
| 端到端时延中位数 | 5135.85毫秒 |
| 端到端时延95分位 | 10268.93毫秒 |

第一圈的60次发布全部按时返回，平均耗时约0.15毫秒，但最少轨迹圈数为2，因此没有形成匹配。第二至第六圈共300次发布全部超过1000毫秒。超时输出按协议丢弃，不参与事后关系回填。最终360次发布没有一组正确关系，宏F1为0。

错误匹配数和重复身份数也为0，原因是没有有效发布匹配。该数值不能说明路线具有零错配能力。计算可用率0.1667同样只表示60次空结果按时返回，不表示关联结果可用。

## 结果分析

共享跟踪器预检通过，说明第二版局部成轨比第一版具备更多可供跨站关联的轨迹。验证集也出现15组正确关系，证明增强几何路线不再被固定门控完全清空。这两项结果关闭了“流程没有任何非零证据仍进入测试”的问题。

路线仍有两个直接缺口。第一，验证召回率只有0.002339，现有门控和确认链路只发布极少关系。第二，轨迹达到两圈后计算量快速增加，第二至第六圈全部超出1000毫秒。测试协议把超时结果作为失败处理，因此少量验证关联能力没有转化为保留测试中的有效在线发布。

当前证据不能把失败归因于单一算法步骤。需要使用逐阶段耗时记录区分共面候选生成、多时刻拟合、全局假设和确认更新的占比。在完成该诊断前，不能仅通过放宽门限或延长截止时间宣称问题已经解决。

## 能力边界

已经验证的内容包括：第二版匿名快照适配、协方差字段换算、输入与冻结指纹检查、测试集冻结前隔离、非零能力失败关闭、20-seed在线调度和超时失败处理。

尚未验证的能力包括：100目标条件下稳定的跨站正确关联、1000毫秒内的逐圈在线发布、达到工程要求的精确率和召回率，以及真实光电传感器条件下的检测与成轨。当前结果不能用于任务分配、目标身份交接或实装能力表述。

## 后续工作

1. 增加逐阶段和逐候选耗时记录，定位第二圈以后计算量增长的位置。
2. 在训练和验证数据内完成共面计算向量化、增量轨迹缓存和有界候选预算，保持测试标签不可见。
3. 预先规定精确率、召回率、F1和时延的联合冻结门限，保留“任一关键指标不满足即停止”的失败关闭规则。
4. 发生算法或参数变化后使用新的标定seed和新的未见测试seed。现有`20270201-20270220`只能作为本轮保留测试证据，不得用于下一轮调参。
