# D1 共同质心原子影子复核

## 结论

原子入口通过安全和只读审计，但没有通过性能门。候选保持默认关闭，A2 不准入，A3、A4
和 seeds 1101/1102 不启动。

clean control/atomic-shadow 的核心墙钟为 `10.735/19.450 s`。影子臂增加
`81.1799%`，高于 `5%` 门限。9 次原子调用的操作后完整性检查全部通过，没有原子失败、
正式航迹替换、下游消费或全局航迹编号变化。46 条候选决策全部因 `oosm_scan` 拒绝，
没有形成 accepted treatment。

## 原子链路

main 在一次同步调用内完成以下步骤：

1. D1 对规范航迹做一次完整描述，形成不可变准备摘要。
2. 结构歧义证据经过时间、数量平衡、发布代次和安全门。
3. accepted 决策才允许构造脱离正式链路的 shadow；rejected 决策不复制航迹。
4. 调用结束前重新核对规范航迹完整内容。核对失败时撤销状态推进并丢弃 provisional
   shadow。
5. main 继续对规范航迹和结构歧义证据做禁止表面前后摘要。结果只进入审计主题，不送
   D2、D3 或控制链。
6. D6 按 `atomic_experimental_offline_v1` 只读检查准备、完整性、工作量、物化和失败字段。

原子入口保留了旧 prepare/evaluate/assemble 公共接口。本轮只切换默认关闭的审计旁路，
没有改变 D1 正式融合输出。

## 原因

本场景的 46 条决策全部被拒绝。旧 prepared-handle 路径在没有 accepted 决策时本来就跳过
shadow assembly。原子入口消除了 accepted 路径可能出现的跨公共调用重复校验，但本次没有
进入该路径。

当前主要成本仍是三部分：

- 原子内部的一次完整规范描述和一次操作后完整性复核；
- main 对规范航迹与歧义证据执行的禁止表面前后摘要；
- 200 规模下的 Python 对象遍历、规范 JSON 和 SHA-256。

原子接口的作用是收紧安全边界。它不是本场景的性能优化。继续在在线主循环中微调该旁路，
收益不足以支撑后续 A3/A4。

## 后续

1. A2 保持默认关闭，不运行 seeds 1101/1102。
2. 共同质心影子改为离线审计候选。在线规则基线不构造完整 shadow 摘要。
3. 结构歧义研究转向 D2 有界概率或多假设层，D1 只发布真值隔离的结构证据。
4. 若继续验证共同质心数学，应先构造真实 accepted 冻结输入，再单独测量 accepted 路径。
5. D1 性能主线回到批量融合、空间预筛选、固定滞后合并重放和延迟序列化。
