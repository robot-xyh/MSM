# G1 影子评分授权合同

## 当前结论

D5 v5 已具备合成数据上的证据资格，但其模型晋级、在线辅助、默认路径、分配、故障接管
和控制权限仍全部关闭。main 新增的授权层只允许模型对确定性 D5 已生成的匿名候选边执行
旁路评分。模型概率不会改变聚类、中心身份绑定、任务分配、降级决策、相机命令或导引控制。

授权合同和运行入口已经通过软件回归。当前没有真实批准文件，也没有正式 G1 episode。
真实相机泛化、中心身份绑定正确率和物理拦截结果仍待验证。

## 状态关系

```text
D5 v5 证据审计通过
        |
        v
g1_evidence_eligible_not_authorized
        |
        | main 在干净提交上生成待审批请求
        v
pending_human_approval
        |
        | 人工核对请求 SHA-256、范围、有效期和固定确认短语
        v
approved_shadow_scope
        |
        | init-scope 冻结授权绑定，run-shard 每次重新校验
        v
authorized_shadow
        |
        +--> 匿名候选边概率、推理时延和摘要写入旁路记录
        |
        +--> 确定性 D5 关联结果继续进入 D3/D4/D7
```

证据资格不是运行授权。影子授权也不是在线辅助授权。模型如需影响在线关联，必须经过新的
独立评审和合同升版，不能修改现有授权文件或 D5 v5 权限字段。

## 冻结范围

每个待审批请求固定记录以下内容：

1. 干净工作树对应的 Git 提交。
2. D5 v5 manifest、完整文件树和权重的 SHA-256。
3. 允许执行的场景、规模、seed、episode 时长和总 cell 数。
4. 推理设备。
5. 生效时间和到期时间。
6. 撤销表身份。
7. 精确的只读影子权限图。

执行计划再次写入授权文件摘要、请求摘要、scope 摘要、模型摘要、设备、有效期、批准身份
和权限图。计划不保存控制文件或模型 bundle 的本机绝对路径。

## 权限边界

| 权限 | 允许值 |
| --- | --- |
| G1 匿名候选边影子评分 | `true` |
| 模型改变在线关联 | `false` |
| 模型晋级 | `false` |
| 中心 `global_track_id` 权限 | `false` |
| 默认路径变更 | `false` |
| 分配权限 | `false` |
| 故障接管权限 | `false` |
| 主动视觉命令权限 | `false` |
| 控制权限 | `false` |

字段缺失、增加、类型错误或任一禁止权限为 true 时，授权文件拒绝加载。

## 运行路径

确定性 D5 先完成候选图、规则边概率、受约束聚类和中心航迹绑定。该结果被保存为在线
权威结果。影子评分器随后读取同一匿名候选图，输出每条边的概率、阈值、推理时延和概率
数组摘要。运行栈分别持有 applied model 和 shadow model；两者不能同时存在。获准影子运行
中 applied model 始终为空。

旁路消息使用 `scalable3d-d5-g1-shadow-scoring-v1`，记录：

- 授权身份、授权文件 SHA-256 和到期时间；
- 模型指纹、节点数和候选边数；
- 每条匿名候选边的模型概率；
- 推理时延、阈值和概率数组 SHA-256；
- 稳定的拒绝原因；
- `model_output_applied=false` 及身份、分配、降级、控制权限为 false。

模型异常、输出维度错误、非有限值、概率越界、阈值错误或推理超时只会形成拒绝记录。
确定性关联结果不随之变化。

## 人工审批

授权控制文件必须保存在仓库外。完整流程分四步：

1. `prepare` 在干净提交上生成待审批请求和空撤销表。
2. 审批人使用 `inspect` 核对请求内容及 `request_sha256`。
3. 审批人使用 `approve` 显式输入请求摘要、身份、理由和确认短语
   `APPROVE G1 SHADOW SCORING ONLY`。
4. main 将批准文件 SHA-256、批准文件和撤销表显式交给 `init-scope`，运行时再把批准文件
   和撤销表交给每次 `run-shard`。

程序不会从证据报告自动生成批准，也不会自动填写确认短语。

## 失败关闭

以下情况禁止创建或继续授权 scope：

- 工作树不干净或 Git 提交与请求不同；
- 批准文件摘要与人工确认值不同；
- 请求、批准或权限字段被修改；
- D5 manifest、文件树、权重或设备发生变化；
- 场景、规模、seed 或时长超出批准范围；
- 授权尚未生效、已经到期或已被撤销；
- 批准文件或撤销表缺失；
- 执行范围包含 G1 以外的变体；
- 恢复分片时授权绑定与原执行计划不同。

撤销表是本地可变控制面。每次分片启动、恢复和新 cell 开始前都重新读取，同时复核当前
Git 提交、工作树状态、授权有效期和作用域。
