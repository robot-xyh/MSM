# D4 v6 来源独立评价

## 结论

D4 v6 边转移动作候选未通过来源独立评价。新数据已经提供足量的规则安全正动作，
但冻结 actor 在 126 帧中没有激活任何转移边。规则正动作命中为 `0/42`，其中 test
为 `0/9`。问题位于 actor 对新资源规模和区域布局的转移激活泛化，不再是评价正类
分母不足。

v6 停止晋级，不进入置信校准、正式留出集、运行预检、D3 后继计划或 D7 控制测试。
确定性规则继续承担区域资源建议。

## 候选

v6 使用共享区域图消息传递网络，并在 v4 连续边输出之外增加独立边激活头。训练损失
包含边激活、有向边排序、正边数量和转移数量。checkpoint 先比较投影后精确动作，再
比较连续损失，避免全不转移模型仅凭较低均方误差入选。

内部 TRAIN/VALIDATION 的正动作命中为 `58/60` 和 `13/15`，负类精确保持 R0 为
`255/290` 和 `55/60`。该结果与冻结 v4 的内部正动作命中相同，负类保持略低。v6
因此只作为新结构候选进入外部评价，内部结果没有被写成模型提升。

候选关键摘要如下：

- manifest 内容 SHA-256：`f40064e7...a6466a83f`；
- 训练审计内容 SHA-256：`ebc1334d...64bee9a`；
- 模型参数内容 SHA-256：`c09d1719...99dba9e6`；
- 状态文件 SHA-256：`e92ea3aa...07b6ea8`。

main 从 clean commit `ed9e086ea8cf5c2138035f710cf4deb3e4a2801e` 生成独立
来源。场景固定为 16 个目标、24 个资源和 8 个区域，保留 8 个备用资源。四类三维
场景分别覆盖 nominal、dense crossing、evasive multilevel 和 delayed noisy。

## 结果

| 指标 | train | validation | test | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 原始转移数 | 0 | 0 | 0 | 0 |
| 投影后转移数 | 0 | 0 | 0 | 0 |
| 精确正动作命中 | 0/24 | 0/9 | 0/9 | 0/42 |
| 负类精确 R0 | 61/65 | 9/11 | 7/8 | 77/84 |
| 不变量失败 | 6 | 6 | 3 | 15 |
| 投影拒绝 | 0 | 0 | 0 | 0 |

15 帧出现节点动作变化，但没有配套 transfer，主要失败原因为
`candidate_transfer_missing`。错误方向、错误数量和虚假转移均为 0，因为 actor
没有激活任何边。这些 0 不能解释为方向和数量学习通过。

规则正类召回有 42 个分母，结果为 0。actor-derived 正类要求 actor 先输出与规则
安全动作一致的可执行签名，本批分母为 0，对应比率保持 unavailable。两个指标不能
合并。

## 独立审计

D6 从冻结 dataset、候选 bundle 和逐帧记录重新构造全部分母与动作结果，没有读取
D4 汇总字段作为事实。D6 得到相同的 `0/42`、`77/84` 和 15 帧不变量失败。

D6 重算 JSONL 与 D4 JSONL 的 SHA-256 均为：

`771826bff66d3ba601d0ffecc95f7ab9faf416826898319de7b9f1669020c7c5`

候选树、source、标签输入和 D4 评价树在审计前后均无变化。模型拟合、checkpoint
更新、阈值调整、置信门应用和正式 holdout 读取均为 0。

## 状态

v6 没有置信校准器。模型内未校准 confidence head 没有进入固定 0.60 门，不能据此
讨论准入。候选继续保持：

- 未注册；
- 准入关闭；
- 强制规则回退；
- assist、分配、降级、接管、联盟、控制和物理权限关闭；
- D3 和 D7 权限关闭。

## 后续

下一步需要另立 actor 版本。新训练数据应增加 M16N24、8 区域安全转移正动作、困难
负类、反向边和拓扑多样性，并恢复负类精确 R0。新 actor 冻结后，先在新的未见
development 数据上取得非零且充分的精确正动作命中，再建立只使用 TRAIN 的置信
校准器。

seed `4016-4079` 已被 D4 和 D6 读取，不能作为下一候选的来源独立评价集。正式
holdout `1000-1019` 继续不读。
