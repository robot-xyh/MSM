# 三维规则全栈性能校准

## 结论

2026 年 7 月 22 日在 detached clean 提交
`33101656b0cf1967a778cdb36a440611e02109b1` 上完成第二轮规则全栈校准。规模为
20、50、100、200，每档使用 seed 42000 至 42004，共 20 个 episode，单例仿真时长
2.2 秒。20/20 状态有限，20/20 `repository_dirty=false`，在线真值使用总数为 0。

平均实时倍率依次为 `1.504/0.540/0.240/0.092`。20 对 20 达到实时；50、100、200
规模仍低于实时。200 对 200 平均墙钟为 23.969 秒，范围为 21.708 至 26.737 秒。

与同配置、同 seed 的上一轮 clean 提交 `492979e` 相比，200 对 200 平均墙钟由
32.711 秒降至 23.969 秒，下降 26.7%；平均实时倍率由 0.068 提升到 0.092，提高
35.9%。D1 融合由 12.103 秒降至 10.275 秒，D2 常规关联由 7.555 秒降至 2.037 秒，
D2 尾部收束由 2.275 秒降至 0.640 秒，D3 分配由 0.870 秒降至 0.665 秒。

200 对 200 仍未达到实时。D1 融合与扫描输入合计 13.041 秒，是当前首要模块瓶颈；
模块发布总线约 2.246 秒，D2 关联与尾部收束合计 2.677 秒。下一阶段应先处理 D1
创新求解、数值雅可比和发布物化，再处理 main 模块栈收束与发布序列化。

本批是干净来源的描述性性能校准。episode manifest 未声明正式实验矩阵，D6 将 20 个
episode 全部归为 `descriptive_clean_source_calibration`，没有升级为正式实验矩阵证据。

## 边界

1. 单例只有 2.2 秒，不能覆盖长历史检查点内存、航迹生命周期、持续机动和物理拦截。
2. 五个 seed 可用于描述性均值和波动，不满足最终 20 个未见 seed 的验收要求。
3. 本批没有 AirSim、真实传感器、真实通信设备或飞控时延。
4. 输出目录受 Git 忽略规则管理；普通提交只保存本报告、固化汇总表和关键哈希。
5. 200 规模实时倍率仍低于 0.10，系统实时性能 P1 继续开放。
