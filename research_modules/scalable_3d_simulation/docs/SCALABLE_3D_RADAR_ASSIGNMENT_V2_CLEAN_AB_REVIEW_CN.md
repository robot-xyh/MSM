# 雷达最大匹配候选评审

## 结论

D1 v2 的最大匹配允许边判定通过模块测试和独立穷举审计，但整分量全抑制策略未通过
200 对 200 系统门槛。首个未见 seed 中，身份交换没有减少，航迹连续性、可用映射、D2
航迹和 D3 分配均下降。本候选保持默认关闭，不运行剩余短 seed、10 秒或 20-seed 扩大矩阵。

该结论针对在线干预方式。允许边图用于识别“同一门内图中存在多个最大匹配”仍然成立。当前
不应把结构歧义直接等同于整分量所有量测都不可用。

## 条件

两组实验均来自 clean commit
`c928727ffa9fdbeee4d9d14184116c1ed178e2fa`，设置为 200 架资源、200 个目标、2 架侦察
节点、2.2 秒、seed 1100。场景配置 SHA-256 相同，均为
`20ef5248c8b45ff5aced9080c8d47e65a43aaba54f18ce824dc50fac7a52b840`。

基线和 v2 只在运行配置中的实验开关上不同。两组 manifest 均为
`repository_dirty=false`，状态有限，在线真值使用为 0。在线观测均为 2,035 条，其中雷达
观测 1,954 条；离线侧车均包含 2,352 条目标标签和 90 条已知虚警标签。

## 结果

| 指标 | 基线 | v2 | 变化 |
| --- | ---: | ---: | ---: |
| 身份交换次数 | 9 | 9 | 0 |
| 航迹连续性 | 0.865 | 0.830 | -0.035 |
| 覆盖连续性 | 0.870 | 0.835 | -0.035 |
| 可用身份映射 | 1,566 | 1,503 | -63 |
| 不可用身份映射 | 230 | 266 | +36 |
| D1 航迹 | 202 | 202 | 0 |
| D2 航迹 | 203 | 199 | -4 |
| D3 分配 | 200 | 196 | -4 |
| 歧义映射 | 0 | 0 | 0 |
| 雷达抑制观测 | 0 | 77 | +77 |

v2 在 9 个扫描中触发结构歧义，抑制 77 条雷达观测，占雷达观测的 3.94%，并让相关航迹
累计 coast 91 次。D1 最终航迹数未变，D2 和 D3 可用量各减少 4。身份交换保持 9 次，
没有形成候选需要达到的身份收益。

## 原因

v2 正确识别了交替环、free-row 路径和 free-column 路径中的最大匹配允许边。独立穷举
2,666 个小规模二部图时，允许边分量与所有最大匹配的 oracle 一致。D1 全量 220 项测试和
可扩展三维 142 项测试通过。

问题出在干预强度。当前策略只要分量含一条可替代边，就抑制分量内所有已匹配和未匹配观测。
该方式避免了虚假确定性，也同时丢失了仍可用于状态更新的几何信息。连续多次 coast 后，D2
可确认航迹和 D3 可分配目标随之减少。结构歧义判定正确，整分量全抑制仍然过于保守。

## 后续

v1 和 v2 均不进入默认在线路径。基线继续使用现有匈牙利分配。身份连续性 P1 保持开放。

下一候选应保留状态信息，限制身份承诺。可研究的方向包括：对歧义分量发布多假设或关联概率；
只冻结身份谱系而继续做协方差保守的状态更新；把歧义证据交给 D2 的联合概率数据关联或多假设
航迹管理。新方案仍需保持双时间戳、协方差、中心拥有的全局航迹编号和在线真值隔离。
