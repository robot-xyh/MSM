# D3 共同检查点物理续跑开发复核

## 结论

2026-07-26 完成 20 个保留随机种子的 5 对 5 名义场景开发复核。规则组和 D3 学习处理组
从同一检查点复制到两个独立三维世界，各续跑 0.5 秒。计划消费、D7 导引血缘、物理窗口和
D6 成对非退化字段均可计算，在线真值使用和 `global_track_id` 改写为 0。

当前 D3 候选没有改变最终资源目标绑定。两组各向世界施加 980 条控制命令，最近距离、
错误绑定、硬约束和五米成功指标完全相同。该结果证明证据生产链可以运行，不能证明学习
代价修正有效，也不能作为 A1 准入证据。

## 多周期区分性复核

为排除 2.2 秒名义检查点过早或 0.5 秒物理窗口过短造成的偶然结果，又对四类场景各运行
一个 6 秒、单 seed、多分配周期的开发诊断。处理组在四个场景中都至少调用了一次学习
策略，规则组和处理组每个周期均形成成对计划，未出现缺失配对。

| 场景 | 学习策略被调用 | 绑定发生变化的周期 | 最终绑定变化 |
| --- | ---: | ---: | ---: |
| 名义 | 是 | 0/6 | 否 |
| 密集交叉 | 是 | 0 | 否 |
| 编队分裂 | 是 | 0 | 否 |
| 规避多高度层 | 是 | 0 | 否 |

四类场景的 `binding_changed_cycle_count` 均为 0，`final_binding_changed_seed_count`
均为 0。现有 D3 development bundle 的代价修正确实进入求解流程，但没有改变任何一个
可执行资源目标绑定。当前阻塞点不是检查点后的物理续跑长度，而是处理计划缺少可观测的
离散决策差异。

## 路径修复

首次运行使用相对输出目录。D6 writer 返回绝对路径，main writer 以相对临时目录执行
`relative_to()`，在原子发布前失败。源计算完成但目标目录未发布，临时目录按异常路径
清理。

`write_checkpoint_paired_physical_rollouts()` 现将输出目录在创建临时目录前统一解析为
绝对路径。既有测试改为从相对目录调用，复核返回路径、D6 文件和重复发布拒绝。专项测试
为 `3 passed, 1 warning`。警告为既有 Matplotlib `Axes3D` 环境提示。

## 下一步

1. 使用预注册的真值无关选择规则，在每个保留 seed 中选择 D3 学习修正能够形成不同可行
   绑定的共同帧。候选帧必须由 D3 版本化证据合同证明同输入、模型实际应用、无规则回退、
   绑定不同且 M 对 N 需求槽完整；main 只按时间顺序选择第一个合格帧。
2. 保持同一初始状态、外生日程、计划有效期、安全外壳和 D7 控制合同，重新执行规则组与
   处理组。
3. D6 同时验收实际学习修正计数、绑定变化、计划消费、物理窗口、硬约束和同键规则非退化。
4. 正式结果必须来自 clean commit；当前脏工作树结果不能被 D3 assembler 消费为准入证据。
