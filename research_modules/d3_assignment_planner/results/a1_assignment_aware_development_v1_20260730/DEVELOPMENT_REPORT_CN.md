# D3 A1 分配感知开发候选报告

## 结论

本轮建立了独立于既有行为克隆 bundle 的 A1 开发候选。候选版本为
`d3_a1_assignment_aware_cost_residual_policy_v1`，bundle schema 为
`d3_a1_assignment_aware_development_bundle_v1`。训练只使用 TRAIN，检查点选择只使用
VALIDATION。外部正式保留种子 `1000-1019` 的读取计数为 0。

验证集包含 320 帧。确定性教师识别出 95 个可形成小范围安全离散变化的正例，其余
225 帧为无需变化负类。所选第 7 轮检查点在 13 个正例上形成安全绑定变化，其中 9 个与
教师替代绑定完全一致。负类 exact-R0 为 `224/225`。有效结果的重复资源、硬禁边、
多机需求不完整和版本违规均为 0。

该结果只证明候选能够在开发数据上跨越部分匈牙利离散边界。它没有经过新来源独立评价，
没有读取正式 holdout，没有运行时采用、控制或物理结果。assist、分配权限、控制权限和
正式准入全部关闭。

## 设计

### 开发目标

旧 A1 以边标签和残差回归为主。历史多周期 shadow 能形成绑定差异，但正式
20-seed/100-frame 评估中仅成本矩阵变化，最终绑定变化为 0。新候选把安全投影后的离散
绑定变化作为检查点选择的首要指标。均方误差和边分类损失保留为训练约束，不再作为唯一
选模依据。

### 教师构造

每帧先以原始规则成本矩阵、硬安全候选掩码和需求槽匈牙利求得 R0。对于仍可行的历史
绑定边，按规则成本差从小到大构造困难候选。候选只提升一条历史边，并抑制同目标的当前
规则边。修正幅度按冻结网格逐级增加。

替代绑定必须同时满足以下条件：

1. 与 R0 的绑定集合不同，绑定对称差不超过 8。
2. 资源不重复，所有边均属于硬安全候选。
3. 多机需求只能完整满足或全部撤回，不能形成部分联盟。
4. 已分配需求槽和高威胁需求槽不低于 R0。
5. 相对历史绑定的重分配数量低于 R0。
6. 在原始规则成本口径下，绝对差不超过 0.10，相对差不超过 0.002。

无法满足上述条件的帧作为负类，目标修正为逐元素零，目标绑定为 exact-R0。

### 学习模型

模型读取现有 12 维候选边特征。边编码器生成共享边表示，帧上下文编码器使用全帧均值、
标准差、极值及历史绑定条件成本统计。模型输出帧级激活门和每条候选边的有界
`delta_C`。最终成本保持：

`C_final = C_rule + alpha * tanh(delta_C)`

其中 `alpha=0.25`，实际单边修正上限为 0.24。离散绑定仍由现有需求槽匈牙利求解器产生。
模型不输出目标编号、资源编号、计划版本、分配计划或控制命令。

训练损失由四部分组成：有界成本修正回归、困难边排名、替代绑定边分类和帧激活分类。
训练集更新模型参数。每轮结束后仅在验证集计算安全离散绑定变化、教师精确匹配、负类
exact-R0 和失败关闭数量。

### 安全外壳

每个模型提议重新经过需求槽匈牙利和多机需求完整性投影。换绑数量、需求覆盖、规则成本
差、硬边和分布范围任一不满足要求时，整帧回退到原始规则矩阵和 R0 绑定。规则矩阵在
模型调用前复制，检查后逐元素比较。

模型及清单中以下权限固定为 false：

- assist；
- assignment authority；
- runtime publication；
- control；
- physical；
- formal holdout；
- production admission。

## 结果

### 所选检查点

第 7 轮检查点在验证集上取得最高安全正类换绑数量，并满足负类 exact-R0 和全部有效安全
门。训练和验证结果如下。

| 指标 | TRAIN | VALIDATION |
|---|---:|---:|
| 非零成本修正帧 | 310 | 104 |
| 安全绑定变化帧 | 32 | 14 |
| 教师正例安全变化 | 31/294 | 13/95 |
| 教师绑定完全一致 | 19/294 | 9/95 |
| 负类 exact-R0 | 667/668 | 224/225 |
| 负类 exact-R0 率 | 99.85% | 99.56% |
| 失败关闭帧 | 254 | 79 |
| 最大有效绑定对称差 | 8 | 8 |
| 重复资源 | 0 | 0 |
| 硬禁边违规 | 0 | 0 |
| 多机需求完整性违规 | 0 | 0 |
| 版本违规 | 0 | 0 |

验证集 79 个失败关闭帧包含换绑数量超限、规则成本差超限和特征分布外输入。一个帧可能
同时具有多个拒绝原因。所有失败关闭帧的有效矩阵和有效绑定均逐项恢复 R0。

### 可复现性

相同输入、配置和随机种子独立训练两次。两次模型文件、manifest 和 bundle tree 摘要
完全一致。

| 制品 | SHA-256 |
|---|---|
| 模型状态 | `c185823bd9a4cf5363d17854385aeb74c340c8ac384327281d224a1097eb8206` |
| manifest | `ec9f93d668e1aa319f65fcda0d73adb0527f316a2d1880e93e88697b6468ad3d` |
| bundle tree | `de7b627df9782d7d2577687f30d02d4faeeaf577ecc557c2b8d91dd6e7115dd9` |
| D3 源码树 | `e2d5e107b985bd71b2ba0899bd2733dae533a502a40ec466cfab8e945e124a25` |

权重使用规范 JSON 和 Base64 张量格式。严格读取器检查固定文件集合、符号链接、文件
摘要、manifest schema、关闭权限、数据分片和模型结构。`assist` 等未授权模式直接返回
规则回退原因。

## 限制

开发教师以小幅增加规则成本换取历史绑定连续性。它为建立可辨识干预提供训练信号，
不能作为收益标签。验证集上的 13 个安全正类变化来自同一数据生成体系，不代表新区域、
新几何或正式种子上的泛化。

负类仍有 1 帧形成安全变化。该变化没有硬约束违规，但说明帧门尚未达到负类全保持。
正式评价前不得降低负类统计口径，也不得将 99.56% 写成 100%。

失败关闭比例较高。其主要来源是模型对多个竞争边同时修正，导致换绑数量或原始规则成本
差超过预注册上限。开发阶段保留这些拒绝，不能通过提高上限换取更多变化。

## 独立评价条件

main 后续可通过严格只读 loader 加载 `build_a/bundle`，但必须使用全新的来源数据和布局。
下一阶段至少满足以下条件：

1. 冻结候选模型、manifest、tree SHA 和 D3 源码树 SHA。
2. 评价数据不得来自本轮 TRAIN/VALIDATION，也不得参与调参和检查点选择。
3. 先运行来源兼容性预检，记录非零修正、安全换绑、负类 exact-R0 和全部拒绝分母。
4. 只有来源独立评价仍有安全正类变化，才考虑预注册正式 `1000-1019` 评估。
5. 正式 holdout 仍需 D6 独立审计，且不能由 D3 回读结果后再次选模。
6. runtime ACK、D7 绑定、物理窗口和同键 R0 非退化形成前，所有在线权限继续关闭。
